# 05 - 模型协议与配置体系

## 1. 设计结论

项目默认原生支持 OpenAI Responses API，但业务和 Harness 不依赖 OpenAI 类型。

Spring AI 作为可选适配器存在，主要用途是：

- 学习框架如何实现 ChatClient、Advisor、Tool Calling 和 Observability。
- 对比自有 Harness 与框架 Harness 的职责边界。
- 未来复用 Spring AI 已支持的 Provider。

任何情况下，`GameRuleEngine`、`PlayerController` 和 Agent Memory 都不能依赖 Spring AI。

## 2. 为什么默认使用 Responses API

相较 Chat Completions，Responses API 更适合 Agent Harness：

- 输入和输出由 Typed Items 表达。
- 原生支持工具调用及工具结果关联。
- 支持 Structured Outputs。
- 支持 reasoning items 和 reasoning summaries。
- 可通过 `previous_response_id` 或 Conversations API 管理连续状态。
- 支持流式 typed events。
- 可以接入 OpenAI 托管工具，但本项目默认只开放受控自定义工具。

旧项目使用 Chat Completions 和 `response_format`。新适配器需要使用 Responses API 的 `text.format` 语义，不继续扩展旧协议模型。

## 3. Model SPI

```java
public interface ModelClient {
    ModelResponse execute(ModelRequest request);
    Flow.Publisher<ModelStreamEvent> stream(ModelRequest request);
    ModelCapabilities capabilities();
}
```

### 3.1 ModelRequest

```java
public record ModelRequest(
        String requestId,
        ModelTarget target,
        List<ModelInputItem> input,
        List<ModelToolDefinition> tools,
        Optional<StructuredOutputDefinition> output,
        ModelGenerationOptions options,
        Optional<ProviderContinuation> continuation,
        Map<String, String> metadata
) {}
```

### 3.2 ModelInputItem

建议使用 sealed hierarchy：

```java
public sealed interface ModelInputItem permits
        InstructionItem,
        UserContentItem,
        AssistantContentItem,
        ToolResultItem,
        ProviderOpaqueItem {
}
```

`ProviderOpaqueItem` 只用于保存和重放 Provider 特有的加密推理等内容。Harness 不解析其内部语义。

### 3.3 ModelResponse

```java
public record ModelResponse(
        String providerResponseId,
        List<ModelOutputItem> output,
        Optional<String> outputText,
        ModelUsage usage,
        ModelFinishStatus finishStatus,
        Map<String, Object> providerMetadata
) {}
```

输出 Item 至少包括：

- `TextOutputItem`
- `StructuredOutputItem`
- `ToolCallOutputItem`
- `ReasoningSummaryItem`
- `ProviderOpaqueOutputItem`

## 4. Provider Adapter

```java
public interface ModelProviderAdapter {
    String providerId();
    ModelClient createClient(ResolvedProviderConfig config);
    ProviderCapabilities describeCapabilities(ResolvedProviderConfig config);
}
```

Provider Adapter 负责：

- 鉴权和 HTTP 协议。
- 统一模型请求到厂商协议的映射。
- 厂商响应到统一 Typed Items 的映射。
- 错误、限流、使用量和完成原因的归一化。
- Provider 特有参数的白名单透传。

Provider Adapter 不负责：

- 选择玩家动作。
- 决定重试是否安全。
- 写 Agent Memory。
- 判断动作是否合法。

## 5. OpenAI Responses Adapter

### 5.1 请求映射

逻辑字段映射：

| Model SPI | OpenAI Responses |
| --- | --- |
| `target.model` | `model` |
| `InstructionItem` | 顶层 `instructions` 或对应 input item |
| `input` | `input` typed items |
| `tools` | function tools |
| `output.schema` | `text.format` Structured Output |
| `options.reasoningEffort` | `reasoning.effort` |
| `continuation.responseId` | `previous_response_id` |
| `metadata` | `metadata` |

### 5.2 Tool Call

工具调用和工具结果通过 `call_id` 关联：

```text
response.output.function_call(call_id)
-> host executes tool
-> next input.function_call_output(call_id)
```

适配器保留 `call_id`，Harness 决定是否执行工具并创建结果。

### 5.3 Structured Outputs

每个动作阶段生成专用 JSON Schema。例如投票阶段只允许：

```json
{
  "type": "object",
  "properties": {
    "publicSpeech": { "type": "string" },
    "action": {
      "type": "object",
      "properties": {
        "type": { "const": "TEAM_VOTE" },
        "vote": { "enum": ["APPROVE", "REJECT"] }
      },
      "required": ["type", "vote"],
      "additionalProperties": false
    }
  },
  "required": ["action"],
  "additionalProperties": false
}
```

不能用一个包含所有阶段字段的巨型 Schema，否则模型更容易选择无关字段。

### 5.4 连续状态

支持三种模式：

- `STATELESS_REPLAY`：本地构建完整必要输入。
- `PREVIOUS_RESPONSE_ID`：保存并链接前次响应。
- `CONVERSATION`：使用 Provider 持久 Conversation。

默认模式是 `STATELESS_REPLAY`。启用后两者时仍要保存本地上下文、事件与 Memory，并具备无 Provider 状态恢复路径。`previous_response_id` 和 Provider Conversation 必须按 `gameId + ownerPlayerId + agentInstanceId` 隔离；相同 Agent Profile 的两个座位也不能共享会话。

顶层 `instructions` 在使用 `previous_response_id` 时仍应每次重新发送。

### 5.5 存储策略

Provider 请求是否 `store` 由配置决定，不由 Agent 自行选择。需要零数据保留时使用 `store: false`，并按协议保存和重放必要的加密 reasoning items。本地 `agent_model_request` 与可选 payload 同样属于玩家私有执行数据，不因 Provider 启用存储而变成共享上下文；详细保留策略见[持久化存储设计与 Phoenix 借鉴](11-持久化存储设计与Phoenix借鉴.md)。

### 5.6 最终动作提交通道

模型可以使用两种协议形式表达最终游戏动作：

```text
STRUCTURED_OUTPUT（默认）
FUNCTION_CALL（兼容模式）
```

认知工具调用可以发生零次或多次；最终动作必须恰好一次。Function Call 模式中的 `submit_team_vote`、`submit_mission_choice` 等函数只能映射为 `ProposedAction`，不能直接修改 Game、Action Batch 或数据库。

同一回合不得同时通过 Structured Output 和 Function Call 提交两个动作。具体批次和幂等规则见 [GameCoordinator 与动作收集规范](12-GameCoordinator与动作收集.md)。

## 6. Spring AI Adapter

Spring AI 2.0.x 适配器实现相同 `ModelClient`：

```text
ModelRequest
-> Spring AI Prompt / ChatOptions / ToolCallbacks
-> ChatClient or ChatModel
-> Spring AI response
-> ModelResponse
```

### 6.1 可复用能力

- ChatClient fluent API
- ToolCallback 和动态 Tool Resolver
- Advisor 链
- Structured Output Converter
- Micrometer Observability
- Provider Starter

### 6.2 必须隔离的部分

- Spring AI `Message` 不进入 Harness 公共接口。
- Spring AI ChatMemory 不成为 Agent Memory 的权威存储。
- Advisor 不直接读取完整游戏聚合。
- ToolCallback 必须复用项目的 Tool Policy 和权限上下文。
- Spring AI 自动重试不得与 Harness 重试叠加为不可控次数。

### 6.3 适配策略

第一阶段不要求 Spring AI Adapter 覆盖所有 OpenAI Responses 特性。它可以声明自己的 `ModelCapabilities`，Harness 根据能力选择兼容路径。

## 7. Capability 模型

```java
public record ModelCapabilities(
        boolean structuredOutput,
        boolean strictStructuredOutput,
        boolean toolCalling,
        boolean parallelToolCalling,
        boolean reasoningEffort,
        boolean reasoningSummary,
        boolean statefulContinuation,
        boolean streaming,
        OptionalInt contextWindowTokens,
        OptionalInt maxOutputTokens
) {}
```

启动时比较 Agent/Harness 需求与模型能力：

- 需要 Tool Calling 但模型不支持：配置失败。
- 不支持 Strict Structured Output：允许使用解析加校验兼容模式，但必须显式开启。
- 上下文窗口小于 Harness 最低预算：配置失败。

## 8. 错误模型

统一错误分类：

```text
AUTHENTICATION
AUTHORIZATION
INVALID_REQUEST
MODEL_NOT_FOUND
CAPABILITY_MISMATCH
RATE_LIMITED
CONTEXT_LENGTH_EXCEEDED
CONTENT_FILTERED
TIMEOUT
NETWORK
PROVIDER_UNAVAILABLE
MALFORMED_RESPONSE
STREAM_INTERRUPTED
UNKNOWN_PROVIDER_ERROR
```

错误对象包含：

- 可重试性建议
- Provider 错误码
- HTTP 状态
- Retry-After
- 请求 ID
- 是否可能已产生计费
- 已接收的部分使用量

Harness 最终决定重试和失败策略。

## 9. Provider 配置

`config/providers.yml`：

```yaml
providers:
  openai-main:
    type: openai-responses
    baseUrl: https://api.openai.com/v1
    credentialRef: env:OPENAI_API_KEY
    connectTimeout: 5s
    readTimeout: 60s
    maxConnections: 20
    storeResponses: false

  openai-compatible-lab:
    type: openai-responses
    baseUrl: https://example.invalid/v1
    credentialRef: env:LAB_API_KEY
    compatibilityMode: LENIENT
    enabled: false
```

`type` 表示协议适配器，配置 ID 表示一个具体连接实例。

## 10. Model Profile 配置

`config/models.yml`：

```yaml
models:
  openai-frontier:
    provider: openai-main
    model: gpt-5.6-sol
    capabilities:
      structuredOutput: true
      strictStructuredOutput: true
      toolCalling: true
      reasoningEffort: true
      statefulContinuation: true
      streaming: true
    limits:
      source: PROVIDER_CATALOG
    defaults:
      reasoningEffort: medium
      maxOutputTokens: 1200
```

示例中的模型名只是配置数据。系统不得在 Java 枚举中固化具体模型。

## 13. 凭据管理

普通 YAML 中只允许 `credentialRef`：

```text
env:OPENAI_API_KEY
file:C:/secure/avalon-secrets.yml#providers.openai-main.apiKey
systemProperty:avalon.provider.openai.api-key
```

解析优先级：

```text
explicit startup override
> environment variable
> external secrets file
> system property
```

不提供 classpath 默认密钥。日志、异常、Trace 和配置查询接口必须脱敏。

## 14. 配置分层与冻结

配置文件分为：

- Provider Registry
- Model Registry
- Agent Registry
- Harness Registry
- Skill Registry
- Rule Pack Registry
- Game Preset

创建游戏时解析引用；开始游戏时冻结：

- Agent Profile 完整内容
- Model Profile 完整内容
- Provider 非秘密配置
- Harness、Skill 和 Memory Policy 版本
- Rule Pack 版本与 Hash

API Key 不进入游戏快照，只保存 Credential Ref。

## 15. 配置校验

启动校验：

- ID 唯一。
- 引用存在。
- Provider 类型已注册。
- Model 能力满足 Harness 要求。
- Skill 版本存在且无冲突。
- Harness 预算合理。
- Credential Ref 格式合法。

开局校验：

- 所有 LLM 座位能解析 Agent。
- Provider 已启用。
- 角色/阶段需要的 Skill 可解析。
- 预算不会超过系统级上限。
- 可选执行 Provider Probe，但不能强制产生高成本调用。

## 16. 配置覆盖

统一优先级：

```text
command line
> environment
> external config directory
> classpath defaults
```

运行中的游戏不自动吸收新配置。新配置只影响后续创建或显式迁移的游戏。

## 17. Provider Probe

提供只读诊断命令：

```text
providers list
models list
model probe <modelId> basic
model probe <modelId> structured
model probe <modelId> tools
```

Probe 结果报告：

- 连接和鉴权
- 实际模型 ID
- Structured Output
- Tool Calling
- 流式响应
- 延迟和使用量

Probe 不自动更改能力配置，只给出差异警告。
