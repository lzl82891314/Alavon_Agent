# 18 - 多世界战略机制具体实现任务计划书

## 1. 目标与边界

本文将 [17 - 多世界假设与战略决策闭环实现报告](17-多世界假设与战略决策闭环实现报告.md) 拆解为可执行任务。实施目标是让 Agent 跨回合维护竞争世界假设、形成可验证预测、比较合法行动并吸收结果反馈。

本轮明确不做：

- 不修改阿瓦隆规则、胜负条件、身份可见性和秘密 Batch 隔离。
- 不把某个牌局的正确队伍、某玩家身份或某轮次决策写成固定规则。
- 不把 `privateThought` 当作正式战略状态。
- 不新增外部依赖。
- 不修改或运行自动化测试，除非用户另行授权。

## 2. 现有代码入口

| 能力 | 当前入口 | 目标变化 |
| --- | --- | --- |
| 请求组装 | `AgentTurnRequestFactory` | 统一组合战略上下文 |
| 证据提取 | `DeterministicStrategicEvidenceAnalyzer` | 从事件生成约束和证据，不输出身份结论 |
| 角色策略 | `RoleStrategyPlanner`、`RoleStrategyPolicy` | 由角色目标和局势生成假设、预测和权重 |
| 记忆持久化 | `PlayerMemoryState`、`MemoryUpdate` | 保存世界、预测、证据和行动摘要 |
| Prompt | `PromptBuilder` | 展示候选比较和反馈要求，不承载推理规则 |
| 校验提交 | `ValidationRetryPolicy`、运行时提交链 | 认知区段独立接受和降级 |
| 决策报告 | `ConsoleDecisionReportBuilder` | 展示世界、预测、候选和反馈生命周期 |

## 3. 任务拆分

### T1：战略状态与兼容迁移

负责范围：`avalon-agent/model`、`avalon-core/player/memory`、运行时记忆提交链。

交付内容：

- 定义 `PossibleWorld`、`WorldConstraint`、`BehaviorPrediction`、`EvidenceAssessment`、`StrategicActionCandidate` 等最小模型。
- 将新字段接入现有 `MemoryUpdate` 和 `PlayerMemoryState`，保留旧 `strategyState` 兼容读取。
- 实现区段级接受、丢弃和 `cognitionDegraded` 语义，禁止缺失新字段覆盖旧状态。
- 所有来源使用 Sequence 引用；不得持久化其他 Agent 私有信息。

验收条件：

- 旧记忆可读取，新字段缺失时保持旧行为。
- 新区段被丢弃不会覆盖已接受区段。
- `privateThought` 不参与正式状态更新。

### T2：通用证据与可能世界生成

负责范围：`avalon-agent/analysis`，必要时只读修改 `AgentTurnRequestFactory`。

交付内容：

- 将任务、投票、公开承诺、公开发言和角色知识转成通用 `WorldConstraint`。
- 生成有限候选世界，应用唯一角色、阵营数量和私有可见性过滤。
- 为世界保存支持证据、反对证据和相对权重，保留主要互斥解释。
- 将任务失败表示为集合约束，不把失败来源直接映射成身份结论。

验收条件：

- 同一输入重复生成结果稳定。
- 所有证据引用均来自当前 Agent 可见事件。
- 不同角色因私有知识不同而获得不同世界视图，但不会越权。

### T3：预测反馈与行动候选评估

负责范围：`avalon-agent/strategy`、`avalon-agent/service`，必要时接入运行时反馈。

交付内容：

- 为主要世界生成行为预测和有效观察窗口。
- 将预测标记为 `SUPPORTED`、`CONTRADICTED`、`INCONCLUSIVE` 或 `EXPIRED`，禁止静默改写。
- 为队伍提案、队伍投票、任务票和刺杀生成统一行动候选。
- 比较阵营价值、信息增益、暴露成本、承诺成本、执行风险和后续计划。

验收条件：

- 复杂行动至少能比较两个候选；只有一个合法动作时比较不同战略执行方式。
- 候选评分有证据引用和后续观察点。
- 行动结果能反馈到对应预测和世界权重。

### T4：角色策略与社会反馈接入

负责范围：`RoleStrategyPlanner`、`RoleStrategyPolicy`、`SocialInfluencePlanner`、`PromptBuilder`。

交付内容：

- 派西维尔维护至少两个可区分的梅林/莫甘娜世界，并生成差异化预测。
- 梅林、忠臣、莫甘娜、刺客使用不同目标权重和风险预算，而非不同固定动作规则。
- 增加公开指控响应计划：直接否认、反驳、部分承认、转移或有理由沉默均为候选策略。
- 记录关键受众、预期反应和实际影响反馈。

验收条件：

- 相同公共局面下，不同角色的世界、预测、目标和候选排序存在结构差异。
- 被公开指控时，模型请求中明确要求回应证据和替代解释。
- 受众计划不泄露私有世界状态。

### T5：生产调用链与决策报告

负责范围：`AgentTurnRequestFactory`、`ConsoleDecisionReportBuilder`、`ConsoleTranscriptPrinter`。

交付内容：

- 将 T1-T4 的正式结构接入真实 LLM 请求。
- 报告并列展示宿主事实、模型原文、已接受认知、世界变化、预测反馈和候选行动。
- 兼容旧游戏记录和字段缺失场景。
- 增加世界创建、预测反馈、行动候选比较和模式迁移的可观测事件。

验收条件：

- 新结构确实进入生产调用链，不存在只定义不消费的 DTO。
- 报告不会把模型原文标记为正式战略状态。
- 旧报告仍可生成。

## 4. 并行依赖

```text
T1 状态模型 -----------+
T2 证据和世界 ---------+--> T3 预测与行动评估 --+
T4 角色与社会反馈 -----+------------------------+--> T5 集成与报告
```

- T1 与 T2 可并行，但字段命名必须先在各自提交说明中固定。
- T3 依赖 T1 的模型定义和 T2 的世界摘要。
- T4 可并行开发角色逻辑，但最终接入由 T5 统一处理。
- T5 负责解决跨 Agent 冲突，不允许多个 Agent 同时重写 `AgentTurnRequestFactory` 和 `PromptBuilder`。

## 5. 监工验收流程

主 Agent 只负责：

1. 审查每个 Agent 的改动是否符合 T1-T5 边界。
2. 检查 DTO 是否真正进入生产调用链。
3. 检查证据 Sequence、可见性和秘密 Batch 隔离。
4. 处理接口命名、构造器和序列化冲突。
5. 执行 `git diff --check` 和 Maven `compile -DskipTests`。
6. 不直接修改生产代码；若发现问题，向负责 Agent 发回修复任务。

## 6. 完成定义

- T1-T5 均有代码落点并通过静态编译。
- 当前牌局中的三个问题可以由“世界假设、预测和候选评估”解释，而不是依赖局部禁用规则。
- 预测不可静默改写，证据不可越权，认知可局部降级。
- 不同角色在同一公开局面下获得可解释的结构差异。
- 决策报告能还原行动前后世界、证据、候选、反馈和正式状态。
- 自动化测试和真实 Provider 多 seed 对局本轮不运行，作为后续行为验收工作保留。
