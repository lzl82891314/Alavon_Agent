## 2. 应用配置

`application.yml`：

```yaml
spring:
  application:
    name: avalon-agent-platform
  flyway:
    enabled: true

server:
  port: 8080

avalon:
  launch-mode: console
  config:
    locations:
      - classpath:/avalon-defaults/
      - optional:file:./config/
    fail-on-warning: false
  runtime:
    max-concurrent-games: 20
    max-concurrent-model-calls: 5
    default-turn-timeout: 45s
    action-collection-policy: default-action-collection-v1
  persistence:
    backend: sqlite
    data-directory: ${user.home}/.avalon-agent
    arena-key: ${user.dir}
    sqlite:
      file-name: avalon-v1.sqlite
      journal-mode: WAL
      foreign-keys: true
      busy-timeout: 5s
    snapshot-every-events: 25
    snapshot-after-round: true
  audit:
    default-level: STANDARD
    store-raw-provider-content: false
  web:
    sse-heartbeat: 15s
```

本地 SQLite 的 JDBC URL 由 `AvalonDataSourceFactory` 根据 `data-directory` 和 `arena-key`
解析，避免把机器相关绝对路径写进 `application.yml`。不要同时再配置一份静态
`spring.datasource.url`；它会绕过 Arena 隔离和数据库生命周期管理。

生产环境使用独立 profile 切换到 PostgreSQL：

```yaml
# application-postgresql.yml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/avalon
    username: avalon
    password: ${AVALON_DB_PASSWORD}

avalon:
  persistence:
    backend: postgresql
```

### 5.1 Action Collection Policy 配置

`action-collection-policies.yml`：

```yaml
actionCollectionPolicies:
  default-action-collection-v1:
    singlePlayer:
      deadline: 45s
      controllerRetryAttempts: 2
      missingSubmissionPolicy: PAUSE_GAME
    teamVote:
      mode: LOGICALLY_PARALLEL
      deadline: 90s
      controllerRetryAttempts: 2
      retryMissingOnly: true
      preserveValidatedSubmissions: true
      disclosurePolicy: REVEAL_ALL_AFTER_COMPLETION
      missingSubmissionPolicy: PAUSE_GAME
      allowHumanTakeover: true
    missionAction:
      mode: LOGICALLY_PARALLEL
      deadline: 90s
      controllerRetryAttempts: 2
      retryMissingOnly: true
      preserveValidatedSubmissions: true
      disclosurePolicy: REVEAL_AGGREGATE_ONLY
      missingSubmissionPolicy: PAUSE_GAME
      allowHumanTakeover: true
    recovery:
      resumePartialBatch: true
      retryCompletedUncommittedBatch: true
      invalidateOnGameVersionMismatch: true
    safety:
      neverGenerateDefaultVote: true
      neverRevealPendingSubmissions: true
      oneActiveBatchPerGame: true
```

`REVEAL_ALL_AFTER_COMPLETION` 用于公开组队投票；`REVEAL_AGGREGATE_ONLY` 用于仅公开任务结果和失败票数量。完整语义见 [GameCoordinator 与动作收集规范](12-GameCoordinator与动作收集.md)。

```yaml
memoryPolicies:
  none:

  structured-episodic-v1:
    type: STRUCTURED_EPISODIC
    maxRecordsPerPlayer: 80
    maxRetrievedRecords: 12
    maxSummaryCharacters: 4000
    mergeSameSubjectAndKind: true
    maxConfidenceDeltaPerTurn: 0.25
    allowedKinds:
      - OBSERVATION
      - SUSPICION
      - TRUST
      - COMMITMENT
      - STRATEGY_NOTE
    requireEvidenceRefs: true
    compaction:
      triggerRecordCount: 60
      retainRecentRecords: 20
      strategy: DETERMINISTIC_FIRST
```

`DETERMINISTIC_FIRST` 表示先做规则化合并；只有仍超预算时才允许使用模型摘要。

## 20. 配置演进规则

- 修改现有配置内容必须提升版本，不能原地改变已发布语义。
- ID 用稳定 kebab-case；Java 类名不进入配置契约。
- 删除配置前检查是否被历史游戏快照引用。
- Provider 实际模型升级通过新 Model Profile 表达。
- Skill 指令发生行为性变化时提升 Skill 版本。
- Rule Pack 变化必须提升版本并生成新 Hash。
- 对旧事件格式使用 Upcaster，不批量覆盖历史事件。
