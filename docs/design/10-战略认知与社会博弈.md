# 10 - 战略认知与社会博弈规范

## 1. 文档级别

本文是 Agent 智能行为的规范性设计，不是可选优化建议。

文中的关键词含义：

- **必须**：不满足就不能宣称实现了战略型 Avalon Agent。
- **应该**：默认实现；只有明确记录理由时才可偏离。
- **可以**：实验性扩展点。

架构、模型和长 Prompt 本身不能保证 Agent 聪明。本项目通过观察契约、认知状态、角色策略、交流协议和评测门槛，把“聪明”转化为可观察、可比较的工程目标。

## 2. 智能行为目标

一个合格的 Agent 必须表现出以下能力：

1. 观察其他玩家的发言、提案、投票和任务结果。
2. 区分游戏事实、他人公开主张和自己的主观推断。
3. 根据新证据更新角色概率，而不是无条件相信最后一位发言者。
4. 识别发言、投票、组队和任务结果之间的矛盾。
5. 形成跨回合目标并记住自己的公开承诺。
6. 根据角色选择不同策略，而不是所有角色执行同一个通用 Prompt。
7. 将私有信念与公开表达分离，允许规则范围内的隐瞒、误导和欺骗。
8. 对他人的质疑作出有针对性的回应。
9. 根据策略选择动作，而不是照抄示例或始终选择最保守动作。
10. 能够解释所用公开证据，但不暴露原始 Chain of Thought。

## 3. 明确禁止的退化实现

以下实现即使能够完成对局，也不符合本规范：

- `PublicGameSnapshot` 只有计分、队长和当前队伍，没有公开事件时间线。
- 每个 Agent 只收到“当前该填什么动作”的表单。
- Prompt 主要内容是“输出最小合法 JSON”。
- 所有 Agent 共用同一策略，只替换模型名称。
- Memory 完全依赖模型主动返回，宿主不采集公开事实。
- 讨论阶段每人固定说一句，不能提问、回应或修正立场。
- Prompt 默认要求诚实，导致邪恶角色不能实施游戏内欺骗。
- 邪恶角色直接公开私有阵营知识，缺少伪装和一致性约束。
- 模型输出合法就算成功，不评估证据使用和战略质量。
- 用更高模型版本掩盖观察空间和执行循环缺失。

## 4. 三层事实模型

Harness 必须明确区分三类信息：

| 层级 | 含义 | 示例 |
| --- | --- | --- |
| `WORLD_FACT` | 规则引擎确认的权威事实 | P2 提议了 P2/P4；第一轮任务成功 |
| `PUBLIC_CLAIM` | 玩家公开说过的话，不保证真实 | P3 声称自己不信任 P2 |
| `PRIVATE_BELIEF` | 当前 Agent 的主观推断 | P2 是邪恶阵营的概率为 0.65 |

不得把 `PUBLIC_CLAIM` 自动升级为事实，也不得把 `PRIVATE_BELIEF` 写回领域聚合。

## 5. 公共观察契约

### 5.1 ObservationBatch

每次 Agent 行动前，Harness 必须提供自该 Agent 上次观察游标之后的完整可见增量：

```java
public record ObservationBatch(
        String gameId,
        PlayerId observer,
        long fromSequenceExclusive,
        long toSequenceInclusive,
        List<ObservedEvent> events,
        PublicGameView currentView,
        PlayerPrivateView privateView
) {}
```

`ObservedEvent` 至少包含：

```java
public record ObservedEvent(
        long sequence,
        String eventType,
        Optional<PlayerId> actor,
        VisibilityLevel visibility,
        Map<String, Object> facts,
        Optional<PublicUtterance> utterance,
        Instant occurredAt
) {}
```

### 5.2 必须可观察的公开信息

- 每次公开发言全文。
- 发言者、顺序和所处讨论轮。
- 发言引用或回应的目标。
- 每次组队提案及提案者。
- 每个玩家的公开投票。
- 组队通过或否决结果。
- 任务成功/失败和公开失败票数量。
- 当前队长、轮次和连续否决次数。
- 已公开的规则事件和管理员允许公开的信息。

### 5.3 绝不能观察的信息

- 其他玩家真实角色，除非角色知识规则允许。
- 秘密任务票与具体玩家的对应关系。
- 其他 Agent 的 Private Belief、Strategy Plan 和 Memory。
- 管理员 Trace。
- Provider 原始响应。

### 5.4 增量与当前快照并存

当前快照用于回答“现在是什么状态”，增量事件用于回答“为什么变成这样”。二者缺一不可。

Harness 必须持久化每个玩家的 `lastObservedSequence`。该记录属于
`gameId + ownerPlayerId + agentInstanceId` 私有作用域；恢复后只能从该玩家可见的 Sequence 继续，不允许因为重启丢失中间发言，也不允许借用其他 Agent 的观察游标或摘要。

## 6. 结构化公开发言

自然语言发言之外，系统记录机器可读的 Speech Act：

```java
public record PublicUtterance(
        String text,
        SpeechActType speechAct,
        List<PlayerId> mentions,
        List<Long> replyToEventSequences,
        List<PublicClaim> claims
) {}
```

`SpeechActType` 初始集合：

```text
STATE_OPINION
ACCUSE
DEFEND_SELF
DEFEND_OTHER
QUESTION
ANSWER
CHALLENGE_CONSISTENCY
PROPOSE_TEST
DECLARE_VOTE_INTENT
REVISE_POSITION
LEADER_SUMMARY
```

Speech Act 是公开话语的索引，不由规则引擎判断真假。它可以由模型结构化输出，也可以由宿主使用轻量解析器补充；原始发言始终保留。

## 7. 战略认知流水线

战略回合必须执行：

```text
Observe Delta
-> Extract Deterministic Evidence
-> Produce Private Belief / Strategy Draft
-> Detect Contradictions
-> Select Role Strategy
-> Plan Desired Audience Belief
-> Choose Speech Act and Game Action
-> Validate Knowledge Boundary
-> Persist private Run Artifacts
-> Submit Proposed Action
-> GameRuleEngine accepts or rejects
-> If accepted, persist formal Strategic State and Checkpoint
```

在提交动作前，Belief、Strategy、Communication Plan 和 Cover Story 只能作为当前
`AgentRun` 的私有 Draft。旧 Turn Token、旧游戏版本或规则校验失败时，Run 必须标记为
`SUPERSEDED` 或 `FAILED`，其 Draft 不得覆盖当前正式认知状态。

对应接口：

```java
public interface StrategicCognitionEngine {
    StrategicTurnResult deliberate(StrategicTurnRequest request);
}

public record StrategicTurnRequest(
        ObservationBatch observations,
        BeliefState priorBeliefs,
        StrategyState priorStrategy,
        RoleStrategyPolicy rolePolicy,
        AllowedActionSet allowedActions,
        AgentBudget remainingBudget
) {}
```

`StrategicCognitionEngine` 位于 `avalon-harness`，不得修改领域状态。

## 8. Belief State

### 8.1 角色假设

```java
public record PlayerBelief(
        PlayerId subject,
        Map<String, Double> roleProbabilities,
        double goodProbability,
        double evilProbability,
        List<EvidenceAssessment> supportingEvidence,
        List<EvidenceAssessment> opposingEvidence,
        List<DetectedContradiction> contradictions,
        ConfidenceLevel confidence,
        long updatedAtSequence
) {}
```

### 8.2 信念约束

- 概率必须在 `[0, 1]`。
- 角色概率之和必须归一化。
- 已被私有知识排除的角色概率必须为 0。
- 对精确已知角色可以固定为 1，但不得公开泄露。
- 每次显著变化必须引用新 Evidence。
- 没有新证据时不得大幅跳变。
- `UNKNOWN` 是合法状态，不强迫 Agent 过早确定角色。

### 8.3 EvidenceAssessment

```java
public record EvidenceAssessment(
        String evidenceId,
        long sourceSequence,
        EvidenceType type,
        Optional<PlayerId> actor,
        String summary,
        double direction,
        double weight,
        String interpretation
) {}
```

`direction` 表示对某假设的支持方向，`weight` 表示证据强度。模型提出解释，宿主验证 Sequence 是否真实且对该玩家可见。

### 8.4 矛盾检测

至少检测：

- 公开声称不信任某人，随后无解释地支持其队伍。
- 承诺拒绝某种组合，随后主动提出同类组合。
- 对相同任务结果给出互斥解释。
- 对被质疑问题回避或改变主题。
- 队伍偏好与历史任务结果长期不一致。

矛盾是证据，不是自动定罪。好人也可能判断错误或改变观点。

## 9. Strategy State

```java
public record StrategyState(
        String currentMode,
        List<StrategicObjective> objectives,
        Map<PlayerId, RelationshipStance> stances,
        List<PublicCommitment> publicCommitments,
        Optional<CoverStory> coverStory,
        Optional<DeceptionPlan> deceptionPlan,
        List<String> unresolvedQuestions,
        long validThroughSequence
) {}
```

Strategy State 是跨回合状态。它必须能够回答：

- 我目前优先验证谁？
- 我公开支持或反对过谁？
- 我希望下一次提案测试什么假设？
- 我是否正在维持一个伪装叙事？
- 哪些新证据会让我改变策略？

## 10. 角色策略规范

```java
public interface RoleStrategyPolicy {
    String policyId();
    List<StrategicObjective> objectives(RoleStrategyContext context);
    StrategyConstraints constraints(RoleStrategyContext context);
}
```

### 10.1 普通好人

目标：

- 最大化可验证信息，而不是盲目追随最强发言者。
- 比较组队、投票和任务结果的一致性。
- 保留不确定性并主动提出可区分假设的问题。
- 在证据变化时允许修正立场，但必须解释变化。

### 10.2 梅林

目标：

- 提高好人选对队伍的概率。
- 避免表现出超出公开证据的确定性。
- 使用普通好人也能获得的证据包装正确判断。
- 必要时故意保留少量不确定或次优判断以降低暴露度。

梅林策略必须维护 `exposureRisk`，但不能为了隐藏身份持续破坏好人胜率。

### 10.3 派西维尔

目标：

- 在梅林候选之间收集区分证据。
- 避免公开确认自己正在保护谁。
- 关注谁拥有异常准确但解释薄弱的判断。
- 在保护梅林与误导刺客之间平衡表达。

### 10.4 莫甘娜

目标：

- 建立“像梅林”的可信度。
- 给出部分正确判断以获得派西维尔信任。
- 避免每次都保护邪恶队友。
- 构造能解释未来行为的稳定公开叙事。

### 10.5 刺客

对局中目标：

- 维持邪恶阵营获胜机会。
- 跟踪具有异常准确率、低证据暴露和引导能力的玩家。
- 不因短期保护队友而放弃梅林识别信息。

刺杀阶段目标：

- 综合全局事件和历史信念选择目标。
- 区分真正梅林、派西维尔和故意吸引刺杀的普通好人。

### 10.6 普通邪恶角色

目标：

- 决定潜伏、切割队友、甩锅或主动领导的时机。
- 不机械地支持所有邪恶队友。
- 根据任务局势决定是否提交失败票。
- 保持公开承诺的一致性，或为策略转向构造合理解释。

### 10.7 奥伯伦、莫德雷德等角色

特殊角色通过独立 `RoleStrategyPolicy` 扩展。策略输入只能包含角色规则允许的私有知识。

## 11. 欺骗与公开叙事

### 11.1 游戏内欺骗是合法能力

Harness 不应对所有角色施加“必须诚实”的通用指令。邪恶角色的误导、梅林的隐瞒和派西维尔的保护性表达都是合法游戏行为。

欺骗只允许作用于游戏内公开表达，不能绕过系统权限、伪造 Tool Result 或访问不可见数据。

### 11.2 私有信念与公开表达分离

```java
public record CommunicationPlan(
        String privateBeliefSummary,
        String strategicObjective,
        Map<PlayerId, String> desiredAudienceBeliefs,
        SpeechActType speechAct,
        Optional<DeceptionIntent> deceptionIntent,
        List<Long> evidenceToMention,
        List<Long> evidenceToWithhold,
        List<String> consistencyRisks,
        String publicMessage
) {}
```

`privateBeliefSummary` 和 `deceptionIntent` 是 PLAYER_PRIVATE 或 ADMIN_ONLY，绝不进入公共事件。

### 11.3 DeceptionIntent

```text
NONE
WITHHOLD_PRIVATE_KNOWLEDGE
UNDERSTATE_CONFIDENCE
OVERSTATE_SUSPICION
CREATE_ALTERNATIVE_EXPLANATION
DISTANCE_FROM_TEAMMATE
BUILD_FALSE_CREDIBILITY
BAIT_ASSASSIN
```

禁止抽象成无限制的“撒谎”开关。每种意图需要角色策略允许，并受一致性检查。

### 11.4 Cover Story

邪恶角色和需要隐藏身份的好人可以维护 Cover Story：

- 当前公开身份形象。
- 已公开的判断依据。
- 支持和反对过的玩家。
- 可以安全承认的错误。
- 不能无解释违反的承诺。

Harness 在生成公开发言前检查新叙事与 Cover Story 的冲突。

## 12. 多轮讨论协议

### 12.1 讨论不是固定独白

默认讨论分为：

```text
OPENING_STATEMENTS
-> CHALLENGE_WINDOW
-> TARGETED_RESPONSES
-> LEADER_SYNTHESIS
-> TEAM_PROPOSAL
```

### 12.2 DiscussionPolicy

```java
public interface DiscussionPolicy {
    DiscussionSchedule nextSchedule(DiscussionState state, DiscussionBudget budget);
}
```

`DiscussionSchedule` 决定：

- 下一位发言者。
- 允许的 Speech Act。
- 是否需要回应指定事件。
- 剩余发言次数和 Token。
- 是否结束讨论。

### 12.3 默认有界规则

- 每位玩家至少一次 Opening Statement。
- 每轮最多两个 Challenge。
- 被直接质疑的玩家获得一次 Response。
- 队长最后获得一次 Leader Summary。
- 每位玩家默认最多三次公开发言。
- 达到讨论 Token、时间或发言次数预算后强制进入提案。
- 讨论调度由宿主决定，模型不能自行无限延长。

### 12.4 选择质疑目标

Challenge 触发条件可以来自：

- 高权重矛盾。
- 某玩家被多个 Agent 提及。
- 队长请求特定玩家解释。
- 当前缺乏区分两个主要假设的信息。

## 13. 观察与记忆闭环

记忆更新分两条路径。

### 13.1 宿主确定性写入

无需模型判断即可记录：

- 谁说了什么。
- 谁提出了什么队伍。
- 谁如何投票。
- 哪个任务成功或失败。
- 当前玩家公开承诺过什么。
- Agent 已观察到哪个 Sequence。

这条路径不能依赖模型主动返回 `memoryUpdate`。

### 13.2 模型解释性写入

模型可以提出：

- 对证据的解释。
- 角色概率变化。
- 矛盾判断。
- 下一步验证计划。
- Cover Story 或 Deception Plan 变化。

Memory Policy 验证 Evidence Ref、变化幅度和可见性后写入。

### 13.3 回合后反馈

每次获得新的任务结果或投票结果后，Agent 应该评估：

- 哪个旧预测得到支持？
- 哪个假设被削弱？
- 哪个公开承诺需要解释或修正？
- 是否需要改变策略模式？

## 14. 战略工具

除基础时间线工具外，应该提供：

| Tool | 作用 |
| --- | --- |
| `get_observation_delta` | 获取自上次游标后的可见事件 |
| `get_public_timeline` | 按轮次、玩家和事件类型查询公开历史 |
| `get_claim_history` | 查询玩家公开主张及其变化 |
| `get_vote_history` | 查询逐人投票和队伍构成 |
| `detect_public_contradictions` | 执行确定性的候选矛盾检测 |
| `compare_team_outcomes` | 比较玩家与成功/失败队伍的关联 |
| `evaluate_team_combinations` | 对候选队伍进行组合分析 |
| `get_my_public_commitments` | 查询自己的公开承诺和 Cover Story |
| `get_my_belief_state` | 读取自己的结构化主观信念 |

工具只整理证据，不直接返回“谁是坏人”的权威结论。

## 15. 模型调用策略

### 15.1 不要求每个阶段都使用相同深度

| 场景 | 推荐认知深度 |
| --- | --- |
| 收到大量新发言后 | 完整 Belief Update + Strategy Plan |
| 队长提案前 | 完整队伍比较和公开叙事规划 |
| 投票前 | 增量更新和动作决策 |
| 任务票 | 复用现有策略，必要时进行简短风险判断 |
| 刺杀 | 完整全局回顾和候选排序 |

### 15.2 自适应两阶段执行

复杂回合默认使用：

```text
Stage A: private strategic analysis
-> structured BeliefUpdate + StrategyPlan

Stage B: public/action generation
-> receives approved private state
-> returns CommunicationPlan + ProposedAction
```

简单回合可以合并为一次调用。是否拆分由 Cognition Policy 和预算决定。

### 15.3 不依赖可见长 CoT

模型不需要输出逐步思维链。系统要求的是结构化中间产物：

- Belief Update
- Evidence Reference
- Strategy Objective
- Desired Audience Belief
- Communication Plan

## 16. Prompt 与示例规范

### 16.1 Prompt 必须强调

- 当前角色目标和特殊信息边界。
- 他人发言是主张，不是事实。
- 阿瓦隆允许游戏内隐瞒和欺骗。
- 必须基于可见 Evidence 更新信念。
- 可以保持不确定，不能无证据确定身份。
- 公开发言应服务于战略目标。
- 最终动作必须满足规则 Schema。

### 16.2 Prompt 不得以格式指令为主体

Structured Outputs 由协议和 Schema 保证。Prompt 不应反复强调：

- 第一个字符必须是 `{`。
- 只返回最小 JSON。
- 私有分析只能一句话。
- Memory 默认省略。

### 16.3 示例防锚定

- 不提供唯一的“先观察”“暂时支持”通用示例。
- 每个阶段至少提供多个差异明显的行为样例，或完全依赖 Schema。
- 示例使用抽象玩家 ID，不暗示固定座位策略。
- 示例不规定所有 Agent 都应保守。

## 17. Agent 差异化

模型不同不等于 Agent 不同。Agent Profile 必须配置策略参数：

```yaml
cognition:
  evidenceDiscipline: HIGH
  uncertaintyTolerance: 0.65
  contradictionSensitivity: 0.75
  informationGainPreference: 0.80
  beliefRevisionRate: 0.35
communication:
  assertiveness: 0.60
  verbosity: 0.45
  challengeFrequency: 0.55
  willingnessToRevisePublicly: 0.40
deception:
  enabledForPermittedRoles: true
  subtlety: 0.70
  teammateDistancePreference: 0.50
  consistencyPriority: 0.85
```

参数是策略先验，不直接决定动作。不同 Agent 应在风险、证据、领导、质疑和欺骗方式上形成稳定差异。

## 18. 预算基线

旧式极低输出预算不适合战略回合。建议逻辑预算：

| 项目 | 默认值 |
| --- | ---: |
| Observation + Memory 输入 | 16,000 Token 上限 |
| Strategy Stage 输出 | 1,500 Token 上限 |
| Public/Action Stage 输出 | 800 Token 上限 |
| 单回合模型调用 | 最多 3 次 |
| 单回合 Tool 调用 | 最多 6 次 |
| 公开发言 | 默认 80 至 300 中文字符 |

Provider 的 reasoning tokens 和可见输出应分别配置。预算不足时优先压缩旧发言，不删除当前增量证据、角色目标和合法动作。

## 19. 战略输出 Schema

```json
{
  "beliefUpdate": {
    "playerBeliefs": [
```

## 20. 智能评测规范

### 20.1 硬性正确性门槛

- 私有信息越权率必须为 0。
- Evidence Ref 必须 100% 指向该 Agent 可见事件。
- 宿主观察游标不得漏掉可见事件。
- 非法动作不得改变领域状态。
- Public Claim 不得被自动写成 World Fact。

### 20.2 场景评测

必须建立以下固定场景：

1. **矛盾识别**：玩家发言与后续投票冲突，Agent 应指出但不能直接断言其角色。
2. **抗从众**：多数玩家提出无证据结论，Agent 应保留独立概率判断。
3. **证据修正**：新任务结果推翻旧假设，Agent 应调整信念并解释变化。
4. **梅林伪装**：梅林引导正确判断，但公开理由只能引用公共证据。
5. **莫甘娜伪装**：莫甘娜给出部分正确判断并维持可信叙事。
6. **邪恶切割**：邪恶角色在适当情境下可以反对队友，而不是机械抱团。
7. **刺杀判断**：刺客综合全局行为识别异常准确的玩家。
8. **回应质疑**：被点名后必须回应具体问题，而不是重复通用发言。
9. **承诺一致性**：违反旧承诺时必须解释变化。
10. **信息不足**：证据不足时保持不确定，不编造事实。

### 20.3 行为基线

战略 Harness 必须与 `baseline-structured-v1` 在相同模型、角色、seed 和座位轮换下比较。

上线战略 Harness 前，至少证明：

- 公开证据引用率显著提高。
- 通用模板化发言重复率显著下降。
- 矛盾识别场景通过率提高。
- 角色专属行为可被统计区分。
- 首次合法动作率不低于基线的可接受区间。
- 平均成本和延迟未超过配置的实验预算。

不以单局胜负判断聪明程度；使用多 seed、角色轮换和置信区间。

## 22. 完成定义

只有同时满足以下条件，才可以宣称新版实现了战略型 Avalon Agent：

- Agent 能看到完整、权限正确的公开增量事件。
- Belief State、Strategy State、Public Commitment 和 Cover Story 跨回合持久化。
- 角色策略在实现和配置中真实存在，不只是 Prompt 中一句“扮演角色”。
- 讨论支持质疑、回应和队长总结，而不是固定独白。
- 私有信念、希望影响的受众认知和公开发言彼此分离。
- 欺骗受角色与安全边界约束，并保持叙事一致性。
- 宿主确定性记录事实，模型只负责解释和策略。
- 场景评测和对照实验表明战略 Harness 优于基线。

这套规范不能保证任何模型在每局都做出最佳决策，但可以保证系统没有从观察、记忆、交互和 Harness 层面先把模型的智能上限压掉。
