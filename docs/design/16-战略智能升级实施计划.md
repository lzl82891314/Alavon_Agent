# 16 - 战略智能升级实施计划

## 1. 目标

本计划负责落实 [15 - 战略智能演进与高级社会博弈](15-战略智能演进与高级社会博弈.md)，将当前以 Prompt 和可选认知草稿为主的战略能力升级为可持久、可解释、可评测的决策闭环。

本轮不追求一次性建立完整博弈搜索器，也不硬编码固定阿瓦隆口诀。实现优先复用现有 `MemoryUpdate`、`PlayerMemoryState`、观察事件、审计元数据和角色策略入口，以最少新增概念打通完整链路。

## 2. 执行约束

- 不修改游戏胜负、可见性和秘密行动披露规则。
- 不让模型访问其他玩家私有状态或当前秘密 Batch 的其他提交。
- 不以 `privateThought` 作为正式战略状态。
- 不增加新的外部依赖。
- 不创建、修改或运行自动化测试、快照和测试夹具。
- Java 修改完成后检查根 POM；当前根 POM 未配置 `maven-checkstyle-plugin`，因此本轮没有强制 Checkstyle 插件命令。若实施期间 POM 状态变化，需要重新确认。
- 最终允许运行 Maven `compile`、`test-compile` 之外的纯静态检查；不得执行测试生命周期。

## 3. 总体交付链路

```text
Observed Events
-> Deterministic Strategic Evidence
-> Persistent Hypotheses and Predictions
-> Role Strategy and Risk Mode
-> Audience / Assassination Context
-> Candidate-aware Prompt
-> Section-level Cognition Acceptance
-> Accepted Action Commit
-> Decision Report and Outcome Feedback
```

## 4. 工作包

### WP0：公共集成契约

负责人：主 Agent。

交付：

- 统一各工作包的数据边界和命名。
- 在 `AgentTurnRequest` 中接入新增战略上下文。
- 在 `AgentTurnRequestFactory` 中组合证据、角色、受众和刺杀信息。
- 在 `PromptBuilder` 中呈现候选比较和回合目标，不增加固定动作示例。
- 处理 sub agent 之间的编译冲突和重复抽象。

完成条件：所有工作包通过单一生产调用链进入真实 LLM 请求，不存在只创建类型但没有消费者的死代码。

### WP1：战略状态可靠性和局部降级

文件域：

- `avalon-agent/.../model/MemoryUpdate.java`
- `avalon-agent/.../model/AgentTurnResult.java`
- `avalon-agent/.../service/ValidationRetryPolicy.java`
- `avalon-agent/.../controller/LlmPlayerController.java`
- `avalon-core/.../player/memory/MemoryUpdate.java`
- `avalon-core/.../player/memory/PlayerMemoryState.java`

交付：

- 将可选认知拆成可独立接受或丢弃的区段。
- 保留机器可读的区段状态、字段路径和失败原因。
- 单一区段失败不再清空全部合法认知更新。
- 增加 `cognitionDegraded` 和已接受区段摘要。
- 为 TEAM_VOTE、MISSION_ACTION 保留最小私有决策摘要，但不公开给其他玩家。

完成条件：合法 action 可提交；合法认知区段可独立保存；失败区段不会覆盖正式状态。

### WP2：投票、队伍和任务的确定性证据

文件域：

- 新增 `avalon-agent/.../analysis/` 包。
- 必要时新增只读战略上下文模型，不直接修改主请求装配器。

交付：

- 从观察事件和公共状态生成投票证据。
- 提取队伍历史、任务结果集合约束和公开立场矛盾。
- 对有限候选队伍计算可解释的相对特征：信念风险、信息覆盖、公开接受风险。
- 所有结果携带来源 Sequence，不输出权威身份结论。

完成条件：给定 `AgentTurnRequest` 已有输入，可生成稳定、只读、权限安全的结构化分析结果。

### WP3：角色假设、反事实预测和策略模式

文件域：

- `avalon-agent/.../strategy/RoleStrategyPlanner.java`
- `avalon-agent/.../strategy/RoleStrategyPolicy.java`
- 新增 `avalon-agent/.../strategy/` 下的角色假设和模式组件。

交付：

- 定义受控的角色策略模式及进入条件。
- 为派西维尔生成梅林/莫甘娜竞争假设。
- 为梅林、莫甘娜、忠臣和邪恶角色提供局势相关目标，而非固定隐藏身份。
- 为刺客从首轮生成并持续更新梅林候选维度。
- 生成可在结果后核对的行为预测摘要。

完成条件：同一公共状态下，不同角色获得结构上可区分的模式、问题和候选假设。

### WP4：社会影响和高风险策略规划

文件域：

- 新增 `avalon-agent/.../social/` 包。
- 不直接修改 `RoleStrategyPlanner` 和主请求装配器。

交付：

- 从公开发言、提案和投票估计关键受众。
- 识别队长、摇摆玩家和高影响玩家。
- 生成目标受众、预期反应和后续观察点。
- 定义主动身份声明计划的最小结构。
- 高风险模式必须包含风险、目标和退出叙事，不直接强迫模型跳身份。

完成条件：公共讨论阶段能够生成非空、证据可追踪的关键受众上下文；证据不足时安全返回空计划。

### WP5：决策报告和可观测性

文件域：

- `avalon-app/.../console/ConsoleDecisionReport.java`
- `avalon-app/.../console/ConsoleDecisionReportBuilder.java`
- `avalon-app/.../console/ConsoleTranscriptPrinter.java`

交付：

- 报告区分模型原始文本、正式接受认知和宿主确定性证据。
- 展示区段接受/丢弃状态和 `cognitionDegraded`。
- 展示策略模式、关键假设、候选行动、受众计划和刺杀候选摘要。
- 缺少新字段时兼容旧游戏记录。

完成条件：旧报告仍可生成；新报告不会把 `privateThought` 标记为正式状态。

## 5. 并行与依赖关系

```text
WP1 State Reliability ---------+
WP2 Evidence Analysis ---------+--> WP0 Integration --> Static Verification
WP3 Role Reasoning ------------+
WP4 Social Influence ----------+
WP5 Reporting -----------------+
```

- WP1 是语义关键路径，但不阻塞其他工作包创建独立组件。
- WP2、WP3、WP4 不得同时修改 `AgentTurnRequestFactory` 或 `PromptBuilder`，统一接入由 WP0 完成。
- WP5 只读取审计和元数据，必须兼容 WP1 尚未出现的新字段。
- 若工作包需要跨域修改，先提交建议，由主 Agent 合并实现。

## 6. 主 Agent 监工职责

主 Agent 不与 sub agent 重复开发业务组件，只负责：

1. 审查每个工作包是否真正连接现有调用链。
2. 拒绝未使用类型、重复 DTO 和只为未来预留的接口。
3. 检查权限边界、秘密 Batch 隔离和 PUBLIC_CLAIM/WORLD_FACT 区分。
4. 合并公共请求、Prompt 和运行时提交链路。
5. 检查 Java 风格、复杂度和异常降级行为。
6. 运行不执行测试的静态编译与差异检查。
7. 更新计划状态和最终实现说明。

## 9. 本轮执行状态

WP0-WP5 已由独立 sub agent 分工完成初版，并由主 Agent 完成主线接入和契约审查。生产代码入口包括：

- `AgentTurnRequestFactory`：组合角色策略、确定性证据和社会影响上下文，并传入真实 Prompt。
- `DeterministicStrategicEvidenceAnalyzer`：生成公开投票、队伍、任务约束和矛盾候选。
- `RoleStrategyPlanner`：按角色和局势提供模式、假设、行为预测及刺杀跟踪维度。
- `SocialInfluencePlanner`：生成队长、摇摆玩家、高影响玩家及高风险身份声明候选。
- `MemoryUpdate`、`PlayerMemoryState` 和运行时提交链：保存区段状态与局部降级结果。
- `ConsoleDecisionReportBuilder`：区分原始模型文本、已接受认知和宿主确定性上下文。

本轮只完成结构化战略闭环和生产调用链接入，不代表真实 Provider 对局已经证明模型具备稳定的高级博弈能力。多 seed、人数、座位和 Provider 组合的行为评测属于后续验收工作。
