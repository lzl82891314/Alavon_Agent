# 17 - 多世界假设与战略决策闭环实现报告

## 1. 文档定位

本文是 [15 - 战略智能演进与高级社会博弈](15-战略智能演进与高级社会博弈.md) 和 [16 - 战略智能升级实施计划](16-战略智能升级实施计划.md) 的实现深化报告。

15 定义能力目标，16 定义工作包；本文回答一个更具体的问题：如何让 Agent 在真实对局中进行可持续的多层推理，而不是遇到一个异常就增加一条固定规则。

本文明确不采用以下方案：

- 不把某个牌局的正确答案写成全局禁用规则。
- 不把“失败队伍成员”“公开反对票”或“高准确率发言”直接映射为某个身份。
- 不用更长的 Prompt 代替状态、预测和反馈机制。
- 不以单一 `evilProbability` 作为全部战略记忆。

实现目标是建立一个通用的决策闭环：

```text
可见事件 + 私有知识
-> 约束化证据
-> 多个可能世界
-> 世界下的行为预测
-> 合法行动候选评估
-> 角色目标加权选择
-> 公开行动与私有摘要
-> 结果反馈
-> 假设和预测更新
```

## 2. 本次牌局暴露的机制缺口

### 2.1 P2 没有反驳指控

当前 Agent 能生成“我支持这支队伍”的策略，但没有把公开指控建模为一个需要回应的社会事件。模型因此可能继续执行原有伪装，而不回答“为什么你不是失败来源”。

这不是莫甘娜专属问题，也不是“坏人必须否认”的规则问题。任何角色被指控时，都需要比较：

- 直接否认是否与已公开行动一致。
- 反指控是否有可引用证据。
- 沉默是否能保留可信度，还是会被群体解释为默认。
- 当前发言的目标是改变队长、摇摆玩家，还是保护更重要的身份。

因此应增加通用的 `accusationResponse` 事件和预测反馈，而不是为莫甘娜写固定反驳文本。

### 2.2 失败后仍选择旧成员

当前候选队伍分析只提供历史重叠等特征，模型可以任意选择“信息增量”叙事，却没有被要求说明该行动在哪些可能世界中获益、在哪些世界中直接输局。

真正缺失的是行动的反事实比较：

```text
H1: 失败来源在 P1
H2: 失败来源在 P2
H3: 失败来源在 P3/P4

队伍 A 在 H1/H2/H3 下的成功概率、信息价值和暴露代价
队伍 B 在 H1/H2/H3 下的成功概率、信息价值和暴露代价
```

模型可以选择冒险，但必须知道自己是在什么世界假设下冒险，以及失败后如何修正判断。

### 2.3 P5 反对票没有转化为公共终局信号

公开反对票不是立即结束游戏的规则动作，但它可能是高信息量的社会信号。系统当前只记录了 `REJECT`，没有持续比较：

- 反对票是否与该玩家此前承诺一致。
- 反对票是否针对队伍结构，而非针对某一身份。
- 反对票是否在高风险比分下具有更高信息量。
- 其他玩家是否根据该票改变队伍和发言。

因此“刺客是否应该立即刺杀”不能由单票硬编码决定，而应作为刺客候选世界的后验变化和行动合法性分离处理。

### 2.4 派西维尔只维护候选名册，没有维护可区分预测

当前已有梅林/莫甘娜候选，但候选没有成为行动选择的输入。派西维尔仍可能选择一个无法区分假设的队伍，因为系统没有计算该队伍是否能让两个假设产生不同预测。

核心改进不是增加“派西维尔要聪明”的提示，而是要求每个候选假设拥有：

- 该假设支持的行为分布。
- 能区分该假设的下一步观察。
- 已经被支持、削弱或仍不可区分的预测。

## 3. 核心抽象：可能世界

### 3.1 定义

`PossibleWorld` 表示在当前 Agent 权限下仍然可能成立的一组角色分配和行为解释。它不是宿主的真实身份表，也不是模型可以读取的答案。

```java
public record PossibleWorld(
        String worldId,
        Map<PlayerId, RoleHypothesisValue> roleAssignments,
        List<WorldConstraint> constraints,
        double priorWeight,
        double posteriorWeight,
        List<Long> supportingEvidenceRefs,
        List<Long> opposingEvidenceRefs,
        List<BehaviorPrediction> predictions,
        long updatedAtSequence
) {}
```

`roleAssignments` 允许 `UNKNOWN`、角色候选集合和阵营候选，不要求每名玩家立即落到单一身份。唯一角色、阵营数量和私有可见信息由宿主过滤不可能世界；公开行为的解释仍由模型负责。

### 3.2 约束类型

约束只表达证据关系，不表达“因此某人就是坏人”：

```java
public record WorldConstraint(
        String constraintId,
        ConstraintKind kind,
        List<PlayerId> subjects,
        List<Long> evidenceRefs,
        String explanation
) {}
```

最小约束集合：

```text
MISSION_SUCCESS_SET       队伍中的可执行任务票均为 SUCCESS
MISSION_FAILURE_EXISTS    队伍中至少存在一个可投 FAIL 的邪恶玩家
PUBLIC_COMMITMENT         玩家曾公开承诺某个队伍或投票方向
VOTE_OBSERVATION          公开揭示的实际投票
CLAIM_CONTRADICTION       公开主张与后续动作不一致
ROLE_VISIBILITY            当前私有知识允许的角色候选
RULE_LEGALITY              动作和阶段合法性
```

任何新的约束类型必须说明来源、权限范围和可反驳条件，不能只添加一个布尔字段。

### 3.3 世界生成与剪枝

世界生成分三步：

1. 根据人数、角色包、唯一性和 Agent 私有知识生成有限角色分配。
2. 应用确定性规则约束，删除不可能世界。
3. 对仍可行世界按公开证据调整权重，而不是删除所有低概率世界。

公开任务失败只删除违反任务集合约束的世界；当失败来源仍不可定位时，不得直接删除所有包含其他成员的世界。

为控制规模，采用 beam search：

```text
生成候选世界
-> 约束过滤
-> 证据似然评分
-> 保留 top-K + 多样性保护世界
```

多样性保护要求至少保留主要互斥解释，避免 beam search 把所有候选压成同一个故事。默认 K 由人数和角色包参数决定，而不是写死在角色 Prompt 中。

## 4. 证据更新机制

### 4.1 证据不是身份结论

`EvidenceAssessment` 只记录某条证据对不同世界的相对支持：

```java
public record EvidenceAssessment(
        long evidenceSequence,
        String evidenceType,
        Map<String, Double> worldLikelihoods,
        String interpretation,
        String uncertainty,
        long assessedAtSequence
) {}
```

例如一次失败任务可以让“P2 是失败来源”的世界权重上升，但不会自动令 P2 的身份概率变成 1。只有当某个世界违反 Agent 的确定性私有知识时，才由宿主过滤该世界。

### 4.2 行为似然

行为似然由 Agent 依据角色目标、已知信息和公开承诺给出区间，而不是精确伪概率：

```text
LIKELY      0.65 - 0.90
PLAUSIBLE   0.35 - 0.65
UNLIKELY    0.10 - 0.35
UNKNOWN     不更新
```

正式状态保存离散标签和依据，避免模型伪造高精度统计。宿主只负责检查范围、来源和更新幅度。

### 4.3 预测反馈

```java
public record BehaviorPrediction(
        String predictionId,
        String worldId,
        PlayerId subject,
        String situation,
        List<String> expectedBehaviors,
        List<Long> discriminatingObservationRefs,
        PredictionStatus status,
        long validThroughSequence
) {}
```

结果发生后只能追加反馈：

```text
SUPPORTED       观察符合预测
CONTRADICTED    观察明显违背预测
INCONCLUSIVE    观察不足以区分
EXPIRED         超过有效窗口仍未观察到
```

旧预测不可被新回合静默改写。预测的作用是避免 Agent 事后为任何行动找到一套新解释。

## 5. 行动评估机制

### 5.1 候选行动

所有复杂行动都转换为统一候选：

```java
public record StrategicActionCandidate(
        String candidateId,
        String actionType,
        Map<String, Object> action,
        Map<String, Double> worldOutcomes,
        double expectedCampValue,
        double expectedInformationGain,
        double exposureCost,
        double commitmentCost,
        double executionRisk,
        List<String> distinguishedWorldIds,
        List<String> followUpPlans,
        List<Long> evidenceRefs
) {}
```

`worldOutcomes` 至少描述任务成功、任务失败、投票通过、投票否决、身份暴露和叙事可信度变化。具体数值可以是模型给出的粗粒度区间，不能假装为规则引擎计算出的胜率。

### 5.2 角色目标加权

每个角色拥有目标权重向量，而不是动作规则：

```text
GOOD:
  missionSecurity, informationGain, publicAccountability, exposureControl

MERLIN:
  missionSecurity, goodGuidance, assassinationSurvival, publicCover

PERCIVAL:
  hypothesisDiscrimination, merlinProtection, missionSecurity, baitControl

EVIL:
  evilWinValue, merlinIdentification, teammateExposureControl, credibility
```

权重由比分、阶段、队伍规模、失败票数量和角色包参数调整。角色可以选择高风险行动，但必须同时提供：

- 触发条件。
- 预期收益。
- 最坏结果。
- 目标受众或目标玩家。
- 失败后的退出叙事。

### 5.3 信息增益定义

信息增益不是“换一支队伍”这么简单。它必须回答行动后世界权重是否会分离：

```text
IG(action) = 当前世界熵 - 预期结果后的世界熵
```

工程实现可以使用粗粒度分箱：

```text
HIGH       能明显区分主要互斥世界
MEDIUM     只削弱部分世界
LOW        结果对所有主要世界都相同
NONE       只是重复已有信息
```

在决胜风险上升时，信息增益不能自动压过阵营胜率；这由角色目标权重和 `executionRisk` 共同决定，而不是由固定轮次阈值决定。

## 6. 社会互动机制

### 6.1 公开指控响应

公开发言事件增加结构化引用：

```java
public record PublicResponsePlan(
        String responseType,
        List<Long> repliedEventRefs,
        String claimToAccept,
        String claimToReject,
        List<Long> evidenceToMention,
        List<Long> evidenceToWithhold,
        List<PlayerId> targetAudience,
        List<String> expectedReactions,
        String exitNarrative
) {}
```

`responseType` 可为 `DENY`、`COUNTERARGUE`、`CONCEDE_PARTIAL`、`REDIRECT`、`SILENCE_WITH_REASON`。系统不规定哪个身份必须使用哪一种，只要求选择有证据、目标和后续计划。

### 6.2 受众状态

Agent 只维护对公开行为的估计：

```java
public record AudienceModel(
        PlayerId audience,
        Map<String, String> publicBeliefSummary,
        double influenceability,
        double decisionLeverage,
        List<Long> publicBasis,
        long updatedAtSequence
) {}
```

发言后的下一次投票、队伍变化和复述行为用于更新影响结果。不能读取受众的私有 `worldHypotheses`。

## 7. 角色实现方式

### 7.1 忠臣和梅林

二者共享世界推理，但目标权重不同。忠臣重点比较任务安全、公开问责和联盟稳定；梅林额外比较指导效果与刺杀暴露成本。

梅林不能因为知道某人是坏人就直接公开指认；它需要评估每个公开理由在主要世界中的可辩护性，以及队伍失败时的替代解释。

### 7.2 派西维尔

派西维尔至少维护两个互斥世界，并为每个世界生成预测。队伍提案前必须说明该队伍：

- 是否区分两个世界。
- 结果若成功或失败分别削弱谁。
- 是否会迫使候选玩家兑现承诺。
- 若不能区分，为什么仍值得承担其风险。

### 7.3 莫甘娜与刺客

邪恶角色共享世界框架，但世界权重包含“梅林在哪个候选中”的维度。莫甘娜重点评估可信度和派西维尔误导；刺客重点评估梅林候选、准确性来源和长期身份暴露。

刺杀阶段只是合法动作窗口，不是推理起点。刺客的候选记录必须从首轮产生，并在每次公开队伍、投票、任务结果和身份声明后更新。

### 7.4 任务行动

任务票仍由规则引擎校验。Agent 的私有决策摘要只记录：

- 可选 `SUCCESS/FAIL`。
- 各世界下的后果。
- 任务票数量对队友暴露的边际影响。
- 预期后续伪装或切割方案。

宿主不读取其他邪恶玩家当前秘密 Batch 的选择，也不把模型声称的意图当作事实。

## 8. 数据契约和调用链改造

### 8.1 `AgentTurnRequest`

新增战略上下文建议保持一个入口：

```java
public record StrategicDecisionContext(
        List<WorldView> possibleWorlds,
        List<EvidenceAssessment> recentEvidence,
        List<BehaviorPrediction> activePredictions,
        List<StrategicActionCandidate> candidateActions,
        List<AudienceModel> audiences,
        List<String> unresolvedQuestions,
        long observedThroughSequence
) {}
```

请求只携带当前 Agent 可见的世界摘要，不携带真实分配表。`AgentTurnRequestFactory` 负责组合，PromptBuilder 只负责渲染，不在 PromptBuilder 中生成战略结论。

### 8.2 `PlayerMemoryState`

将当前单一 `strategyState` 逐步兼容扩展为：

```json
{
  "worldHypotheses": [],
  "activePredictions": [],
  "evidenceAssessments": [],
  "actionAssessments": [],
  "audienceModels": [],
  "commitments": [],
  "strategyMode": "...",
  "cognitionDegraded": false,
  "observedThroughSequence": 0
}
```

旧字段继续保留，作为当前主目标和兼容展示字段；新字段成为跨回合推理的正式来源。

### 8.3 接受和降级

新认知区段继续使用局部接受：

```text
worldHypotheses
predictions
evidenceAssessments
actionAssessments
communicationPlan
```

任一区段被丢弃时，不能覆盖其他已接受区段。若 `worldHypotheses` 缺失，宿主保留旧世界摘要并标记 `cognitionDegraded`；不得用默认身份结论填充。

## 9. 决策报告要求

每个行动至少展示：

1. 行动前保留的主要世界及相对权重。
2. 本次行动引用的公开证据和私有可见证据。
3. 至少两个候选行动及其世界区分能力。
4. 选中行动的目标权重、风险和后续计划。
5. 上轮预测的反馈状态。
6. 模型原文、正式接受认知和宿主事实的边界。

报告不得只展示“P4 认为 P3+P4 更好”，而应展示“该选择在 H1/H2/H3 下分别意味着什么”。

## 10. 分阶段实施

### Phase A：只读世界摘要

- 新增 `PossibleWorld`、`WorldConstraint`、`BehaviorPrediction` 数据结构。
- 从现有公开事件生成有限世界摘要。
- 不改变动作选择，只在决策报告和 Prompt 中展示。

验收：世界摘要来源可追踪，不能包含越权身份信息。

### Phase B：预测和反馈

- 将行动前预测写入私有记忆。
- 下一次相关事件到达时生成 `SUPPORTED/CONTRADICTED/INCONCLUSIVE`。
- 报告展示预测生命周期。

验收：旧预测不可被后续回合覆盖，认知局部失败可恢复。

### Phase C：候选行动评估

- 为队伍提案、队伍投票、任务票和刺杀生成统一候选。
- 将世界区分能力和阵营目标权重接入模型输出。
- 仍由规则引擎执行最终动作。

验收：每个复杂行动至少存在两个可比较候选；只有一个合法动作时，比较不同叙事和风险执行方式。

### Phase D：社会反馈

- 增加公开指控响应计划。
- 记录目标受众和实际反应。
- 将公开承诺、投票和后续行为接入证据更新。

验收：被指控时不再默认静默；沉默也必须是有说明的候选策略。

### Phase E：角色参数化和评测

- 将角色差异从 Prompt 文本迁移为目标权重、候选偏好和风险预算。
- 按人数、角色包、比分和 Provider 参数化。
- 建立多 seed、座位轮换和角色轮换对照实验。

验收：不同角色在相同公开局面下的世界假设、预测、候选评分和行动偏好具有可统计区分度。

## 11. 评测指标

### 11.1 推理闭环

- 世界假设保留率。
- 主要世界覆盖率。
- 预测兑现率和反事实区分率。
- 行动后预测反馈延迟。
- 旧预测被静默改写次数，目标为 0。

### 11.2 战略质量

- 任务安全与阵营胜率。
- 信息增益与实际可区分结果的一致性。
- 公开承诺兑现和矛盾检测准确率。
- 被指控后的有效回应率。
- 高风险行动与局势风险的相关性。
- 刺客从首轮开始维护候选的覆盖率。

### 11.3 可靠性边界

- 私有信息越权率必须为 0。
- Evidence Ref 可见性通过率必须为 100%。
- 非法动作改变领域状态次数必须为 0。
- 认知区段丢弃不得覆盖已接受战略状态。
- 任务秘密 Batch 隔离违规次数必须为 0。

单局胜负不能作为完成证据。至少需要相同模型、相同角色包、相同 seed 集合下的基线对照，并报告置信区间。

## 12. 完成定义

只有满足以下条件，才可以宣称完成本机制升级：

- Agent 能跨回合维护多个仍可能成立的世界，而不是只有一个身份概率表。
- 每个关键行动都有行动前预测和行动后反馈。
- 队伍、投票、任务和公开发言使用同一套证据与行动评估抽象。
- 角色差异体现在目标权重、风险预算和预测内容，而不只是角色 Prompt。
- 宿主负责事实、约束、合法性和权限；模型负责解释、比较和选择。
- 公开指控会触发可评估的回应策略，不会默认沉默或默认认罪。
- 派西维尔和刺客能持续维护竞争假设，而不是在最后阶段临时猜测。
- 决策报告能解释“为什么这个行动在多个可能世界下值得选择”。
- 多 seed、角色轮换和人数变化实验显示该机制稳定优于当前单一概率和模板化基线。
