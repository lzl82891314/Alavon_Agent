# 15 - 战略智能演进与高级社会博弈

## 1. 文档定位

本文是 [10 - 战略认知与社会博弈规范](10-战略认知与社会博弈.md) 的后续演进 Spec，专门描述真实对局暴露出的未完成能力和下一阶段实现目标。

两份文档的边界如下：

| 文档 | 定位 | 状态含义 |
| --- | --- | --- |
| `10-战略认知与社会博弈.md` | 战略 Agent 的基础能力、信息边界和通用 Harness 规范 | 已有设计基线；具体实现程度以代码和评测为准 |
| 本文 | 在基础规范之上补齐高级推理、角色差异、社会影响和可靠战略闭环 | 默认全部为待实现目标，不能因写入文档而宣称完成 |

本文中的关键词含义：

- **现状**：当前代码或真实对局已经观察到的行为，不代表能力稳定通过。
- **缺口**：基础设计已经提出，但当前实现或评测尚未形成闭环。
- **必须**：本阶段完成定义中的强制要求。
- **应该**：默认实现，偏离时必须记录原因。
- **候选技巧**：可由 Agent 根据局势选择的策略，不是硬编码动作规则。

后续每完成一个实施阶段，必须在独立实现记录、评审报告或评测报告中留下证据。本文只定义目标，不在正文中把目标改写成“已完成”，从而保持现状和未来能力可区分。

## 2. 问题陈述

当前系统已经具备观察隔离、角色私有知识、结构化认知草稿、多轮讨论和动作校验骨架，但真实对局仍表现出明显退化：

- 所有角色都倾向“先隐藏、先稳妥、继续观察”。
- 发言能够复述投票和任务结果，却不能说明这些结果区分了哪些角色假设。
- Agent 能偶尔生成合理的私有分析，却不能稳定地跨回合维护目标、承诺和叙事。
- 角色目标主要以 Prompt 文本存在，没有稳定驱动策略模式和具体动作。
- 欺骗虽然被允许，但 Agent 不会评估何时承担高风险欺骗值得。
- 投票和任务是最重要的信息来源，却经常只被当作时间线中的普通事件。
- 刺客容易在最终刺杀阶段才集中判断梅林，而不是从首轮持续追踪。
- 不同角色使用相似的谨慎模板，缺少可统计区分的角色行为。

这说明当前缺少的不是更多游戏术语，而是以下决策闭环：

```text
Public Events + Private Knowledge
-> Deterministic Evidence
-> Competing Role Hypotheses
-> Role-specific Strategy Mode
-> Candidate Action Comparison
-> Audience Influence Plan
-> Proposed Action
-> Outcome Feedback
-> Persistent Strategic State
```

## 3. 优化边界

### 3.1 不以加长 Prompt 代替决策内核

以下做法不能单独作为本 Spec 的完成证据：

- 增加更长的角色说明或更多技巧示例。
- 更换更强模型但不改变证据、状态和行动闭环。
- 只展示模型的 `privateThought`，不证明正式战略状态已被接受和延续。
- 以一局中偶然出现某个高级技巧作为能力证明。
- 以合法动作率代替战略质量评测。
- 把人类经验硬编码成所有局面都执行的固定动作。

### 3.2 宿主和模型的职责

宿主负责：

- 权威事实、可见性和观察游标。
- 投票、队伍、任务和公开承诺的确定性关系提取。
- 不可能角色假设过滤。
- 动作合法性、认知区段校验和状态提交。
- 预测、实际结果和评测证据的关联。

模型负责：

- 对合法可见证据进行解释。
- 比较竞争角色假设。
- 选择角色策略模式和风险预算。
- 规划公开叙事、欺骗和关键受众影响。
- 在候选合法动作之间作出战略选择。

宿主不得直接输出“谁是坏人”的权威结论，模型也不得绕过规则引擎直接改变游戏状态。

## 4. 战略状态可靠性

### 4.1 动作与认知分离提交

动作合法性和认知质量必须采用独立结果：

```text
Required Action
-> strict validation
-> ProposedAction

Optional Cognition Sections
-> section-level validation
-> accepted sections + warnings
-> Strategic Draft
```

`action` 合法时，单个认知区段失败不得使合法动作失败；认知区段失败也不得静默伪装成成功写入。

认知至少拆分为：

- `beliefUpdate`
- `hypothesisUpdate`
- `evidenceAssessments`
- `strategyState`
- `communicationPlan`
- `audienceBeliefUpdate`
- `assassinationTracking`

每个区段独立记录 `ACCEPTED`、`DISCARDED` 或 `NOT_PROVIDED`。`DISCARDED` 必须保存字段路径和机器可读原因。

### 4.2 最小正式战略状态

每次被规则引擎接受的行动后，宿主必须保证该 Agent 至少拥有以下正式状态：

```java
public record MinimumStrategicState(
        String currentMode,
        String primaryObjective,
        List<RoleHypothesis> leadingHypotheses,
        List<String> unresolvedQuestions,
        List<PublicCommitment> activeCommitments,
        long observedThroughSequence,
        long sourceActionSequence
) {}
```

如果模型没有提供合法更新，宿主仍必须推进观察游标、公共事实、投票历史、任务历史和公开承诺。

宿主不得自行伪造模型主观结论。缺失的主观字段保持旧值或 `UNKNOWN`，并记录 `cognitionDegraded=true`。

### 4.3 原子动作的私有决策记录

`TEAM_VOTE` 和 `MISSION_ACTION` 对其他玩家仍然只披露原子动作，但 Harness 必须允许在提交前形成私有决策记录：

```java
public record PrivateActionAssessment(
        String actionType,
        List<ActionCandidateAssessment> candidates,
        String selectedCandidate,
        List<Long> decisiveEvidenceRefs,
        String expectedInformationGain,
        String expectedFollowUp,
        long validAtSequence
) {}
```

该记录属于 PLAYER_PRIVATE 或 ADMIN_ONLY，不进入公共事件，也不要求保存原始 Chain of Thought。

### 4.4 结果反馈

下一次观察到投票揭示或任务结果时，必须执行：

```text
Load previous prediction
-> compare actual outcome
-> mark supported / weakened / unresolved
-> update hypotheses
-> reconsider strategy mode
```

系统必须能回答“上轮行动希望验证什么，以及结果实际验证了什么”。

## 5. 投票、队伍与任务证据

### 5.1 投票是一等证据

每次公开组队投票必须生成结构化 `VoteEvidence`：

```java
public record VoteEvidence(
        long revealSequence,
        int roundNo,
        int proposalNo,
        List<PlayerId> proposedTeam,
        PlayerId voter,
        VoteChoice vote,
        List<PublicCommitmentRef> relevantCommitments,
        List<DetectedContradiction> contradictions,
        GameScore scoreBeforeVote
) {}
```

确定性分析至少提供：

- 玩家是否在队伍中。
- 玩家此前是否公开支持或反对该组合、成员或组队原则。
- 当前投票是否违反仍有效的公开承诺。
- 同一玩家在相似队伍上的投票是否发生变化。
- 谁形成关键通过票或关键否决票。
- 连续否决计数和当前比分是否改变该票的风险含义。

宿主只输出关系和矛盾候选，不直接把某票解释为邪恶身份。

### 5.2 队伍组合比较

队长提案、组队投票和任务结果分析前，应该生成有限的候选队伍比较：

```java
public record TeamCandidateAssessment(
        List<PlayerId> team,
        double estimatedMissionSuccess,
        double informationGain,
        double identityExposureRisk,
        double publicAcceptanceLikelihood,
        List<String> hypothesesDistinguished,
        List<String> strategicRisks
) {}
```

候选比较至少回答：

- 该队伍成功或失败分别支持哪些假设？
- 结果能否区分主要嫌疑人，还是只会制造新的等价歧义？
- 当前比分是否允许用任务胜率换取信息？
- 该队伍是否会迫使某个玩家兑现公开承诺？
- 对梅林、派西维尔和邪恶方分别有什么身份暴露影响？

“最稳妥”不是默认最优目标。系统必须显式比较任务胜率、信息增益和长期阵营胜率。

### 5.3 任务结果归因

经典规则下，任务结果只能产生集合约束：

```text
0 fail -> team members all chose SUCCESS in this mission
1+ fail -> at least one eligible evil player in the team chose FAIL
```

任务证据必须结合队伍历史、公开主张和投票行为形成多个竞争解释。宿主不得把某玩家“声称自己投 SUCCESS”升级为世界事实。

对于存在多名已知邪恶成员的任务，邪恶 Agent 应评估失败票数量造成的身份暴露风险，但不得读取队友在当前秘密 Batch 中尚未公开的选择。

### 5.4 核心战略工具

以下工具属于本阶段核心能力：

1. `get_vote_history`
2. `compare_team_outcomes`
3. `evaluate_team_combinations`
4. `detect_public_contradictions`
5. `get_claim_history`

工具必须返回结构化证据和来源 Sequence，不返回最终身份结论。

## 6. 角色假设与反事实推理

### 6.1 竞争角色假设

仅维护每名玩家的 `evilProbability` 不足以支持多层推理。Agent 必须能够维护互斥或竞争的角色分配假设：

```java
public record RoleHypothesis(
        String hypothesisId,
        Map<PlayerId, String> candidateRoles,
        double relativeConfidence,
        List<Long> supportingEvidenceRefs,
        List<Long> opposingEvidenceRefs,
        List<BehaviorPrediction> predictions,
        long updatedAtSequence
) {}
```

宿主应根据人数、角色唯一性和私有排除条件过滤不可能假设，但不替模型选择最终解释。

### 6.2 反事实行为预测

对关键角色候选，Agent 应在行动前形成可验证预测：

```java
public record BehaviorPrediction(
        String hypothesisId,
        PlayerId subject,
        String situation,
        List<String> expectedBehaviors,
        List<String> discriminatingObservations,
        long validThroughSequence
) {}
```

预测用于回答：

- 如果某人是梅林，他在当前公开证据下更可能支持哪些队伍？
- 如果某人是莫甘娜，他是否可能在不知道梅林精确身份时把梅林带入队伍？
- 如果某人是派西维尔，他会如何在两个候选人之间收集区分证据？
- 如果某人是刺客，他是否在牺牲短期任务利益以观察谁在精准引导？

真实行为发生后，预测必须标记为 `SUPPORTED`、`CONTRADICTED` 或 `INCONCLUSIVE`，不得事后重写旧预测。

### 6.3 派西维尔候选区分基线

当派西维尔只知道两个玩家分别为梅林和莫甘娜时，必须维护至少两个竞争假设，例如：

```text
H1: P1=MERLIN, P4=MORGANA
H2: P1=MORGANA, P4=MERLIN
```

若 P1 主动提出包含 P1 与 P4 的队伍，派西维尔应评估：

- 该行为在 H1 下是否符合梅林已知莫甘娜身份后的预期？
- 该行为在 H2 下是否符合莫甘娜不知道精确梅林身份时的预期？
- P4 对该队伍的发言和投票是否进一步区分 H1/H2？

该场景是反事实推理的验收基线，不是“提出该队伍者必为莫甘娜”的硬编码规则。

## 7. 风险收益决策

### 7.1 候选行动比较

复杂回合不能直接从观察跳到单一动作。至少比较两个合法候选；若只有一个合法动作，则比较该动作的不同战略执行方式。

```java
public record ActionCandidateAssessment(
        String candidateId,
        String actionSummary,
        double campWinValue,
        double informationGain,
        double identityExposureRisk,
        double narrativeConsistency,
        double executionRisk,
        List<String> expectedResponses,
        List<String> followUpPlans
) {}
```

最终选择必须说明当前优先级：

```text
WIN_MISSION
GAIN_INFORMATION
PROTECT_ROLE
MISDIRECT_KEY_PLAYER
PRESERVE_ASSASSINATION_LINE
FORCE_COMMITMENT
RECOVER_CREDIBILITY
```

### 7.2 风险档位

Harness 不得通过通用指令隐式奖励“永远隐藏身份、永远选择争议最小队伍”。至少支持：

```text
LOW_RISK_CONTROL
BALANCED_PROBE
HIGH_INFORMATION_PROBE
IDENTITY_PRESSURE
DESPERATION_PLAY
```

高风险行动只有在潜在收益、失败代价和后续计划被记录时才算战略行动；随机激进不算高级博弈。

### 7.3 邪恶任务票分工

邪恶角色在任务中必须评估：

- 当前任务是否必须失败才能维持胜率。
- 队伍中已知邪恶人数。
- 多张失败票是否会暴露邪恶数量或协同行为。
- 自己的角色价值和公开可信度是否值得保留。
- 队友在规则允许的私有知识下可能采用什么策略。

经典 5 人角色配置下，可以把“莫甘娜优先保留梅林伪装、刺客承担失败票”作为候选协调惯例，但不得写成无条件规则。协调只能依靠角色惯例、既有计划和公开状态。

## 8. 社会影响与受众认知

### 8.1 受众信念估计

公开发言的目标不能只是说出自己的判断。Agent 应维护关键受众的可见认知估计：

```java
public record AudienceBeliefEstimate(
        PlayerId audience,
        Map<String, Double> estimatedBeliefs,
        List<Long> publicBasis,
        double influenceability,
        double decisionLeverage,
        long updatedAtSequence
) {}
```

该估计只能基于受众公开发言和行动，不能读取其他 Agent 的真实私有状态。

### 8.2 关键受众

每次重要公开表达前，Communication Plan 应选择主要影响对象：

- 当前队长。
- 尚未承诺投票方向的摇摆玩家。
- 能影响多数人的高话语权玩家。
- 派西维尔或梅林候选。
- 刺客认为可能暴露梅林的关键观察者。

系统必须区分“我相信什么”和“我希望谁相信什么”。

### 8.3 影响反馈

发言后必须观察：

- 目标玩家是否改变公开立场或投票。
- 其他玩家是否复述、反驳或忽略该叙事。
- 自己的可信度是否上升或下降。
- 是否意外暴露了特殊角色知识。
- 是否使新的玩家成为讨论中心。

只生成 `desiredAudienceBeliefs` 而不评估实际影响，不构成社会博弈闭环。

### 8.4 多人局

人数增加时，策略必须考虑：

- 影响所有人通常不可行，应选择有限关键受众。
- 普通忠臣的联盟和投票方向可能比特殊角色身份更决定短期队伍结果。
- 角色知识覆盖比例下降后，公开话语、投票联盟和领导权重上升。
- 不同人数、角色包和任务阈值需要不同风险参数和策略先验。

## 9. 角色专属策略模式

### 9.1 模式契约

`StrategyState.currentMode` 必须来自受控但可扩展的模式集合。每个模式必须定义：

- 进入条件。
- 优先目标。
- 偏好的证据和行动。
- 允许的欺骗意图。
- 退出或降级条件。
- 失败后的恢复方式。

### 9.2 正义方

普通忠臣至少支持：

```text
INFORMATION_SEEKING
COALITION_BUILDING
VOTE_PATTERN_PRESSURE
LEADER_ACCOUNTABILITY
IDENTITY_BAIT
MISSION_SECURITY
```

普通忠臣可以在高阶策略中公开声称自己是派西维尔或梅林候选，以吸引注意、保护特殊角色或测试他人反应，但必须记录风险、目标受众和退出叙事。

梅林至少支持：

```text
GUIDE_WITH_PUBLIC_COVER
CONTROLLED_UNCERTAINTY
DECOY_SUPPORT
PROTECT_GOOD_TEAM
REDUCE_EXPOSURE
EMERGENCY_DIRECTION
```

`REDUCE_EXPOSURE` 不得长期压倒阵营胜率。连续因隐藏身份而支持明显低质量队伍，应判定为战略退化。

派西维尔至少支持：

```text
CANDIDATE_DISCRIMINATION
PROTECT_MERLIN
BAIT_ASSASSIN
FALSE_PERCIVAL_CLAIM
CONTROL_PUBLIC_FOCUS
```

派西维尔可以主动成为讨论焦点，但必须说明希望从哪些玩家的反应中获得什么信息。

### 9.3 邪恶方

莫甘娜至少支持：

```text
BUILD_MERLIN_CREDIBILITY
PARTIAL_TRUTH_LEADERSHIP
MISDIRECT_PERCIVAL
DISTANCE_FROM_TEAMMATE
CONTROLLED_SABOTAGE
FALSE_ROLE_CLAIM
```

刺客至少支持：

```text
MERLIN_TRACKING
LOW_VISIBILITY_SABOTAGE
TEAMMATE_COVER
TEAMMATE_SACRIFICE
PROBE_ACCURATE_PLAYERS
ASSASSINATION_COMMIT
```

刺客必须从首轮开始维护梅林候选，不得等到 `ASSASSINATION` 阶段才首次建立候选排序。

普通邪恶角色至少支持：

```text
INFILTRATE_TEAM
CONTROLLED_SABOTAGE
DISTANCE_FROM_TEAMMATE
FRAME_GOOD_PLAYER
FORCE_BAD_CHOICE
DESPERATION_PLAY
```

### 9.4 主动身份声明

主动声称特殊身份必须作为结构化策略事件记录：

```java
public record PublicRoleClaimPlan(
        String claimedRole,
        String strategicPurpose,
        List<PlayerId> targetAudience,
        List<String> expectedReactions,
        List<String> consistencyRequirements,
        String exitNarrative,
        double assessedRisk
) {}
```

允许的候选策略包括邪恶角色假装派西维尔、派西维尔吸引刺杀、普通忠臣假装派西维尔保护特殊角色。宿主只验证游戏内权限和叙事一致性，不判断声明真假。

## 10. 刺杀目标的全局维护

### 10.1 规则动作与战略目标分离

经典规则包中，刺客只有在正义方完成规定数量的成功任务后才能提交 `ASSASSINATION` 动作。若扩展规则允许提前刺杀，必须由 Rule Pack 明确定义，不能由 Prompt 绕过规则引擎。

无论动作何时合法，刺客识别梅林的战略目标必须贯穿整局。

### 10.2 候选评分

刺客至少维护：

```java
public record AssassinationCandidate(
        PlayerId playerId,
        double merlinLikelihood,
        double percivalLikelihood,
        double deliberateBaitLikelihood,
        double unexplainedAccuracy,
        double influenceOnGoodTeams,
        List<Long> decisiveEvidenceRefs,
        long updatedAtSequence
) {}
```

重要特征包括：

- 在公开证据不足时持续避开邪恶玩家。
- 能引导正确队伍但避免直接领导。
- 故意保留少量错误或不确定性。
- 谁在保护另一个可能的特殊角色。
- 谁主动制造刺杀诱饵。
- 判断准确度与公开理由之间是否存在异常差距。

最终刺杀必须比较至少两个候选，并区分梅林、派西维尔和主动诱饵。

## 11. 实施阶段

### 11.1 P0：战略状态可靠性

交付：

- 认知区段独立校验和独立接受。
- `cognitionDegraded` 与丢弃原因可观测。
- 原子动作的私有决策记录。
- 最小正式战略状态和回合后预测反馈。

验收：认知单字段失败不丢失其他合法字段；下一轮能读取上轮已接受目标、假设和预测。

### 11.2 P1：确定性证据与候选比较

交付：

- `VoteEvidence`
- `TeamCandidateAssessment`
- 任务集合约束分析。
- 公开承诺和投票矛盾检测。
- 核心战略查询工具。

验收：决策报告能够展示某次行动引用的投票、队伍、任务和承诺证据，而不是只展示自然语言解释。

### 11.3 P1：角色假设和模式执行

交付：

- 竞争角色假设。
- 行为预测及结果反馈。
- 角色专属模式进入和退出条件。
- 刺客全局候选维护。

验收：相同模型在不同角色和相同公开局面下产生可统计区分的目标、模式和动作偏好。

### 11.4 P2：社会影响与高风险策略

交付：

- Audience Belief Estimate。
- 关键受众选择和影响反馈。
- 主动身份声明计划。
- 欺骗、诱饵、切割和牺牲策略。

验收：高风险动作具有明确触发条件、目标受众、预期反应和退出计划；重复运行中不会退化为随机激进。

### 11.5 P2：人数与规则包适配

交付：

- 按人数和角色配置选择策略参数。
- 多人局联盟和影响力分析。
- 可选提前刺杀等扩展规则的显式 Rule Pack 契约。

验收：不同人数下的角色行为不是简单复用 5 人局 Prompt。

## 12. 评测规范

### 12.1 硬性正确性门槛

- 私有信息越权率必须为 0。
- Evidence Ref 必须 100% 指向该 Agent 可见事件。
- 秘密任务 Batch 中不得读取其他玩家尚未披露的选择。
- 被丢弃的认知区段不得覆盖正式状态。
- 反事实预测不得在结果发生后静默改写。
- 非法动作不得改变领域状态。

### 12.2 高阶场景

必须覆盖：

1. **派西维尔反事实区分**：根据梅林/莫甘娜候选的组队、投票和回应比较互斥假设。
2. **邪恶任务票分工**：多名邪恶上队时，根据角色价值、比分和暴露风险选择 SUCCESS 或 FAIL。
3. **投票主轴推理**：连续多轮追踪某玩家公开立场、队伍关系和投票变化。
4. **信息与胜率权衡**：在可承受比分下选择高信息队伍，在决胜任务中转向任务安全。
5. **身份诱饵**：好人或邪恶角色主动声称特殊身份，并利用他人反应继续行动。
6. **社会影响**：选择关键摇摆玩家作为受众，并在后续投票中评估影响是否生效。
7. **刺客持续追踪**：从首轮维护梅林候选，终局不得只依据最后一轮发言。
8. **认知降级恢复**：一次认知区段校验失败后，后续回合仍保留其他已接受战略状态。

场景不要求唯一标准动作，但必须检查证据、候选比较、角色目标、风险说明和后续计划是否完整。

### 12.3 对照实验

必须在相同模型、角色、seed、人数和座位轮换下与现有 Harness 比较，并分别报告：

- 胜率。
- 战略场景通过率。
- 角色行为可区分度。
- 通用模板化发言重复率。
- 高风险策略的局势相关性。
- 首次合法动作率。
- 认知区段接受率和降级率。
- 平均成本和延迟。

不以单局胜负判断聪明程度；必须使用多 seed、角色轮换和置信区间。

## 13. 可观测性与决策报告

新增指标：

```text
avalon.agent.hypothesis.created
avalon.agent.hypothesis.prediction_accuracy
avalon.agent.vote_evidence.used
avalon.agent.team_candidates.compared
avalon.agent.cognition.section_discarded
avalon.agent.cognition.degraded_turns
avalon.agent.role_claim
avalon.agent.audience.influence_result
avalon.agent.assassination.candidate_revisions
avalon.agent.strategy.mode_transitions
```

管理员决策报告应按回合并列查看：

- 公开事件和秘密信息边界。
- 确定性投票、队伍、任务和矛盾证据。
- 行动前的主要竞争假设。
- 候选行动的风险收益比较。
- 已接受和被丢弃的认知区段。
- 当前角色模式及其进入原因。
- 目标受众、预期影响和实际反馈。
- 刺客的候选变化历史。

报告必须明确区分模型原始文本、已接受正式认知和宿主确定性事实。`privateThought` 不能被当作正式战略状态的证明。

## 14. 完成定义

只有同时满足以下条件，才可以宣称完成本文定义的战略智能升级：

- 认知区段失败可局部降级，不会让 Agent 丢失全部战略状态。
- 投票、队伍和任务结果经过确定性结构化分析，而不是仅作为长文本输入。
- 关键角色能够维护互斥假设、形成行为预测并在结果后反馈。
- 角色策略能够驱动模式和行动选择，不只是 Prompt 中一句“扮演角色”。
- 投票和任务原子动作拥有私有战略决策记录。
- 刺客从首轮持续维护梅林候选。
- 公开发言具有关键受众、预期影响和结果反馈。
- 高风险身份声明、欺骗、诱饵和切割具有触发条件、风险预算和退出计划。
- 不同人数和角色配置使用不同策略参数，而不是机械复制 5 人局行为。
- 高阶场景评测和对照实验表明新 Harness 稳定优于现有基线。

本 Spec 不保证模型每局都做出最佳决策，也不把人类经验硬编码成唯一答案。它要求系统持续提供合法信息、可靠状态、可比较候选、角色差异和结果反馈，使模型有条件进行真正的多层社会博弈，而不是退化为谨慎的游戏日志总结器。
