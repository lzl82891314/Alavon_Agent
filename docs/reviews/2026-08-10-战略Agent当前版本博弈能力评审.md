# 战略 Agent 当前版本博弈能力评审

评审日期：2026-08-10  
评审对象：当前分支 `f09e974` 及其之前提交的 Agent Harness、Runtime 和核心领域代码。  
评审目标：确认新版是否仍会退化为“按流程打卡、无条件相信、不会欺骗”的 Agent。

## 1. 结论摘要

**不能宣称当前项目已经实现了战略型 Avalon Agent。**

当前版本已经解决了前身最危险的信息差问题：从代码路径看，正式 Agent 上下文只读取自己的 `memoryOf(playerId)`，公开观察经过白名单投影；投票和任务动作在同一冻结状态下生成；梅林、邪恶同伴和派西维尔的知识矩阵不再直接暴露不允许的精确角色。因此，前身那种“所有 Agent 实际共享全局私有信息，导致博弈失效”的确定性问题目前没有复现证据。

但是，战略认知的核心仍未闭环。`BeliefState`、`StrategyState`、`CommunicationPlan` 和 `CoverStory` 大部分只是模型返回的 Map；宿主主要校验概率范围、变化幅度和证据编号，没有确定性地验证矛盾识别、角色允许的欺骗、公开承诺连续性、策略状态有效性或动作收益。一个模型完全可以输出固定的 `INFORMATION_SEEKING`、一次形式上的概率变化和一个空 `coverStory`，从而满足结构评估，却没有真正进行社会推理。

因此当前判定为：

| 维度 | 判定 |
| --- | --- |
| 私有信息隔离 | 基本通过代码审查 |
| 公开事件观察与冻结投票 | 基本通过代码审查 |
| 角色策略存在性 | 部分通过：有角色提示和角色目标，但缺少宿主执行约束 |
| 信念/证据认知 | 部分实现：有概率和证据边界，但没有语义质量保证 |
| 欺骗与伪装 | 未通过：主要依赖模型自报，且允许越权意图 |
| 质疑/回应 | 协议存在，但调度固定，语义未验证 |
| 真实模型博弈能力 | 未验收：当前模型档案全部禁用，未有真实 Provider 对局证据 |

## 2. 已确认的正向能力

### 2.1 没有发现跨 Agent Memory 入口

`TurnContextBuilder` 通过 `state.memoryOf(player.playerId())` 构造当前玩家 Memory，随后 `MemoryContextProjector` 只投影该对象。没有发现把 `memoryByPlayerId` 整体送入 Agent 请求的路径。

### 2.2 公开观察默认白名单

`PlayerObservationProjector` 只投影 `GameEventVisibilityPolicy.isPublic(event.type())` 为真的事件；未知事件默认为私有。`ROLE_ASSIGNED` 不在公开白名单中，角色分配事件不会进入普通 Agent 观察增量。

### 2.3 秘密批次动作使用冻结上下文

投票和任务阶段会先为所有参与者构造 `PlayerTurnContext`，再调用 Controller，最后统一提交结果。后生成的 Agent 不会看到本批次先生成的票或任务选择。

### 2.4 角色差异已经进入运行时 Prompt

`RoleStrategyPlanner` 对 Merlin、Percival、Morgana、Assassin、Mordred、Oberon 和普通好人提供不同目标、约束和允许的 deception intent。这比前身所有 Agent 共用一个通用流程 Prompt 有实质改善。

## 3. 关键问题

### P1：角色欺骗权限没有宿主校验，越权欺骗可以被接受

`RoleStrategyPlanner` 只把 `permittedDeceptionIntents` 放入模型上下文；`ValidationRetryPolicy` 校验的重点是 `roleBeliefs` 和 Evidence Ref，没有校验 `strategyState.deceptionIntent` 是否属于该角色允许集合，也没有检查 `coverStory` 是否与角色策略冲突。

结果是好人可以自报 `BUILD_FALSE_CREDIBILITY`，Oberon 可以自报与规则不符的队友知识，评估器还会把非 `NONE` intent 计为欺骗计划。该问题直接破坏“欺骗受角色与安全边界约束”的设计契约。

证据：`avalon-agent/src/main/java/com/example/avalon/agent/strategy/RoleStrategyPlanner.java:23-29,56-64`；`avalon-agent/src/main/java/com/example/avalon/agent/service/ValidationRetryPolicy.java:71-104`。

### P1：战略状态是模型自报，未形成确定性认知闭环

`PlayerMemoryState.merge` 会直接用模型提供的 `roleBeliefs`、`strategyState` 和 `communicationPlan` 替换旧值；公开承诺也只来自 `commitmentsToAdd`，并非由已提交的公开发言自动记录。宿主没有检查：

- `strategyState` 是否包含有效 mode/objective/unresolvedQuestions；
- 新发言是否兑现或解释旧的 public commitment；
- `communicationPlan` 是否与最终 `PublicSpeechAction` 一致；
- belief change 的方向是否与证据相符；
- contradiction 是否真实存在、是否被模型处理。

这意味着模型可以每回合返回同一套模板字段，系统仍会把它持久化为“战略状态”。这正是前身“进度总结工”退化的主要剩余入口。

证据：`avalon-core/src/main/java/com/example/avalon/core/player/memory/PlayerMemoryState.java:101-108`；`avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:384-446`。

### P1：战略评估器不在运行时强制链路中，且门槛容易被刷过

`StrategicBehaviorEvaluator` 位于 `avalon-testkit`，当前没有发现它被 `GameCoordinator`、`GameOrchestrator` 或应用服务用于拒绝/标记生产对局。评估逻辑也只统计字段和 Speech Act：一次概率变化即可计作 belief revision，非空 deception intent 或 coverStory 即计作 deception plan，没有验证决策是否改善阵营胜率、是否影响受众，或是否是角色合法行为。

因此 `meetsStrategicGate()` 不能证明 Agent 聪明，只能证明输出看起来像战略 JSON。它无法阻止“固定模板 + 一次形式变化”的退化实现。

证据：`avalon-testkit/src/main/java/com/example/avalon/testkit/StrategicBehaviorEvaluator.java:30-80`；`avalon-testkit/src/main/java/com/example/avalon/testkit/StrategicBehaviorReport.java:24-30`。

### P1：当前没有真实 LLM、多 seed、角色分层的行为证据

五个仓库模型档案的 `enabled` 均为 `false`，请求中没有可用 Provider 凭据。因此当前不能根据代码或离线演示声称真实模型已经会质疑、欺骗、切割和刺杀识别。

设计文档要求固定场景、同模型基线、角色轮换和多 seed 对照；这些是外部验收项，目前没有可审计的实验结果。

证据：`avalon-app/src/main/resources/model-profiles/*.yml`；`docs/design/10-战略认知与社会博弈.md:653-681`。

### P2：noop 回退策略本身仍然是机械策略，且任务失败后不会更新队伍信念

`NoopAgentGateway` 只在 `observationDelta` 中寻找 `MISSION_FAILED`，并把失败影响施加给 `currentTeam`。但任务结算随后清空当前队伍；下一次讨论请求通常已经没有 `currentTeamPlayerIds`，所以该回退策略不会把刚刚失败的任务成员纳入信念更新。未知玩家还长期使用固定 `0.4` 先验。

这不代表真实 LLM 一定有同样 bug，但意味着无 Provider 时的默认演示会继续呈现“固定先验 + 规则动作”的非博弈行为，不能作为新版成功样本。

证据：`avalon-agent/src/main/java/com/example/avalon/agent/gateway/NoopAgentGateway.java:37-70,149-164`；`avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:318-345`。

### P2：讨论协议有互动外形，但调度是固定仪式，缺少确定性矛盾/证据工具

每轮固定经历所有 Opening、最多两个 Challenge、被点名者 Response、Leader Synthesis。宿主没有根据高权重矛盾、争议集中度或信息区分需求动态选择质疑目标；项目中也没有设计文档列出的 timeline、claim history、vote history、contradiction 和 team outcome 工具实现。

因此讨论不会再是“一人一句”的纯独白，但仍可能退化为每局都执行相同话术模板。当前评估器只检查是否点名和引用回复事件，不检查回应是否回答具体问题。

证据：`avalon-runtime/src/main/java/com/example/avalon/runtime/model/GameRuntimeState.java:316-369`；`docs/design/10-战略认知与社会博弈.md:484-500`。

### P2：私有知识表达校验存在整句不确定词绕过

`PrivateKnowledgeExpressionValidator` 以逗号、句号等切分语句；只要一个子句包含“可能/怀疑”等不确定词，就跳过整个子句的确定性角色断言检测。模型可以构造“可能 P2 是梅林，但 P3 就是刺客”这样的混合句式绕过检查。该问题同时影响候选角色断言和精确私有角色公开表达校验。

证据：`avalon-agent/src/main/java/com/example/avalon/agent/service/PrivateKnowledgeExpressionValidator.java:40-55,79-107,126-142`。

### P2：Agent 差异化配置结构存在，但默认没有形成差异

`PlayerAgentConfig` 有 cognition/communication/deception 字段，`RoleStrategyPlanner` 也会透传它们；但仓库模型档案只配置模型连接参数，没有默认策略 Profile。未显式提供配置时所有同角色 Agent 使用空参数，差异主要只来自模型随机性和角色文字目标，无法保证稳定的风险偏好、质疑频率或欺骗风格差异。

## 4. 对用户关切的直接回答

### 是否还会访问其他 Agent 的私有记忆？

从当前正式代码路径看，没有发现。该项可以判定为**代码级通过**，但仍应保留管理员审计接口只对管理员开放的集成验证。

### 是否还会因看到精确角色而失去信息差？

常规 Merlin、邪恶同伴和 Percival 知识投影已按规则限制；没有发现前身同类的确定性泄漏。私有知识表达校验有语句绕过，但它是模型公开表达边界问题，不是其他 Agent 直接读取私有数据。

### Agent 是否已经懂得博弈、欺骗和质疑？

**尚不能确认，代码结论偏否定。** 角色目标和 Prompt 已经为博弈提供了输入条件，讨论协议也支持 Challenge/Response；但欺骗权限、承诺一致性、矛盾检测和策略收益没有落成宿主约束，且没有真实对局证据。因此仍可能出现“形式上填写战略字段、行为上机械打卡”的 Agent。

## 5. 建议的验收顺序

1. 先在宿主校验中实现角色允许的 deception intent、strategy schema、communication/action 一致性和公开承诺自动采集。
2. 从公开事件确定性计算 contradiction、claim history、vote history 和 team outcome，模型只解释这些证据。
3. 修正 noop 基线，使任务失败证据绑定到任务队伍，而不是依赖结算后的 currentTeam。
4. 增加至少两套有明显差异的 Agent Profile，并在相同模型、角色、seed、座位轮换下对比 `baseline-structured-v1`。
5. 使用矛盾识别、抗从众、证据修正、梅林伪装、莫甘娜伪装、邪恶切割、刺杀判断、回应质疑和承诺一致性场景，至少运行 20 个 seed；报告证据引用率、模板重复率、角色区分度、非法意图率、胜率/置信区间、成本和延迟。

## 6. 最终判定

当前版本相较前身已经完成了“先把信息差和执行边界做正确”的重要第一步，但还没有完成“证明 Agent 真正在社会博弈”的第二步。**可以称为具备战略 Harness 雏形，不能称为已实现高博弈能力；前身那种无脑信任和按部就班退化仍有现实可能，只是原因已从私有信息泄漏转移为战略状态缺少宿主约束、评测不可阻断以及默认 noop/配置缺少行为差异。**

本评审未修改业务代码，未运行自动化测试或真实 Provider 对局。
