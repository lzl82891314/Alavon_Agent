# 战略 Agent 第五轮整改后复审报告

复审日期：2026-08-10  
评审对象：当前工作区相对《战略 Agent 第四轮整改后复审报告》的最新修改。  
评审范围：私有知识表达分句、Memory/Observation 送模去重、公开承诺修正、输出契约。

## 1. 结论

本轮三项整改均已在代码路径中生效：

- `PrivateKnowledgeExpressionValidator.clauses()` 现在先替换连接词，再进行分句，上一轮指出的“替换发生在 split 之后”问题已修复。
- `AgentTurnRequestFactory` 会根据送模 Memory 中已有的 Claim Sequence 过滤 Observation Delta，历史 Memory 与增量输入不再重复展示同一公开事件。
- `REVISE_POSITION` 已改为只尝试更新与当前发言 `mentions` 重叠的 ACTIVE Commitment，不再无差别改写全部历史承诺。
- Prompt 输出示例已移除会被主机静默丢弃的 `publicCommitments` 和 `commitmentsToAdd` 字段。

当前仍有一个 P2 级承诺语义缺口：**承诺修正依赖 `mentions` 与旧记录 `targets` 的字符串重叠；当修正发言没有 mentions，或旧承诺没有 targets 时，承诺不会被修正。** 这使承诺状态是否闭环取决于模型是否恰好填充了非强制的目标字段。

此外，Commitment 仍为 `List<String>` JSON，主机虽然提供了替换逻辑，但尚未达到强类型、可查询、可兑现的设计目标。真实 Provider 行为、角色差异和稳定博弈效果仍未验收。

## 2. Findings

### P2：REVISE_POSITION 的承诺更新依赖非强制 mentions，存在漏更新路径

当前修正逻辑要求：

```java
ACTIVE commitment
&& commitment.targets 与 revision.mentions() 有交集
```

但 `TARGETED_RESPONSES` 的运行时校验只强制 `replyToEventSequences`，不强制 `mentions`；`REVISE_POSITION` 本身也没有独立的目标字段。因此以下合法动作不会更新原承诺：

- “我改变之前的判断，现不再支持原方案。”（`mentions=[]`）
- 旧承诺是兼容历史数据的 JSON/字符串，没有 `targets` 字段。
- 修正的是队伍组合或投票条件，而不是单个玩家，无法通过玩家 ID 重叠识别。

结果是新立场被记录为 ACTIVE，但旧承诺仍保持 ACTIVE，后续一致性分析会把一次明确修正误判为矛盾或同时存在的两个承诺。

证据：

- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:478-480`
- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:492-520`
- `avalon-runtime/src/main/java/com/example/avalon/runtime/model/GameRuntimeState.java:324-328`

建议在 `REVISE_POSITION` 的结构化动作中加入必填 `supersedesSequence`（或明确的被修正对象/主题），由宿主按 Sequence 精确更新。若没有可识别对象，应保留旧承诺为 ACTIVE，并把当前发言仅记录为新的立场声明，不要假设它已经修正了旧承诺。

### P2：正式 Commitment 仍是 JSON 字符串，状态契约尚未类型化

`PlayerMemoryState.commitments` 仍为 `List<String>`，`mergeCommitments()` 通过正则提取 `sourceEventSequence` 来替换旧值。该实现解决了部分重复追加，但以下能力仍缺失：

- 类型系统无法保证 `status`、targets、condition、supersedes 字段存在且类型正确；
- 无法稳定查询某个玩家、队伍或投票意图的承诺；
- `REVISED` 只是一段 JSON 中的字符串状态，没有统一状态迁移约束；
- 旧格式字符串会被保留，导致同一列表内存在多种不可比较格式。

证据：`avalon-core/src/main/java/com/example/avalon/core/player/memory/PlayerMemoryState.java:20,168-194`。

这不是本轮新增回归，但仍是战略 Harness 从“记录发言”走向“可验证承诺”的主要结构缺口。建议新增强类型 `PublicCommitment`，模型建议与宿主接受状态分离。

## 3. 已确认修复

- 连接词替换现在发生在分句之前，不确定词整句绕过的原实现顺序错误已修复。
- `isCertainMatch()` 会把匹配区间本身纳入局部不确定性判断，`P2可能是梅林` 不再因为 marker 位于 player alias 之后而被误判为确定断言。
- 送模前会过滤已在 Memory Claim 窗口中的 Observation Event，上一轮“同一句话在 Memory 和 Observation 同时出现”的直接问题已修复。
- REVISE 不再批量修改所有 ACTIVE 承诺，而是至少按 targets 交集筛选。
- Prompt 不再要求输出会被主机静默丢弃的 `publicCommitments` 和 `commitmentsToAdd`。
- Claim 已包含 `actorPlayerId`、`eventType` 和稳定 Sequence，Memory 合并按事件序列幂等。

## 4. 总体博弈能力判断

当前版本已经基本保持了私有信息隔离：没有发现 Agent 可以读取其他 Agent 的私有 Memory、私有行动结果或模型响应。公共发言、世界事实、跨回合 Memory、角色欺骗白名单、Evidence 引用和讨论协议均已形成可执行骨架。

但代码仍只能证明“模型有机会进行博弈”，不能证明“模型稳定进行博弈”。战略工具、动态争议调度、完整角色候选 Belief、承诺兑现检测、真实 Provider 多 seed/座位轮换和 baseline 对照仍缺少行为验收。
