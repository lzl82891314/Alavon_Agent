# 战略 Agent 第三轮整改后复审报告

复审日期：2026-08-10  
评审对象：当前工作区相对上一轮《战略 Agent 第二轮整改后复审报告》的最新修改。  
评审范围：Agent 输出校验、公开 Claim/Commitment 写入、Observation 游标、跨回合 Memory、战略能力验收链路。  

## 1. 结论

本轮修改正确修复了上一轮的两个 P1，并处理了两个 P2 的直接症状：

- 最终公开文本现在取解析后的 `PublicSpeechAction.speechText` 进行私有知识表达校验，`action.speechText` 绕过已关闭。
- 没有候选身份知识时不再提前返回，精确私有身份知识的公开表达检查能够执行。
- `enrichPublicCommitment()` 会保留 Observation 生成的 `publicClaimsToAdd`，其他玩家的公开发言不再因 Memory 合并而永久丢失。
- 普通问题、回答、观点和总结不再全部写入 Commitments。
- `modelCommitments`、`modelPublicClaims` 不再被临时塞入自由结构 `strategyState`。

但本轮在“立即记录自己的公开发言”与“按 Observation 游标再次消费事件”之间产生了新的 P1 级 Memory 一致性问题：**同一条自己的公开发言会在下一回合同时出现在历史 Memory 和 Observation Delta 中，并在提交后永久重复保存。** 这会让模型看到重复证据、挤占上下文窗口，并使后续矛盾与承诺分析建立在非幂等数据上。

此外，私有知识表达校验的“不确定词整句放行”仍然存在；Commitment 虽已缩小写入范围，但仍是不可更新的 JSON 字符串，尚未形成设计文档要求的确定性、结构化承诺状态。

因此当前判定是：

- 其他 Agent 私有 Memory/身份信息的读取隔离仍然成立，没有发现回归。
- 上一轮两个直接 P1 已修复。
- 跨回合公开认知的完整性较上一轮提高，但尚未通过幂等性要求。
- 代码已经具备比前身项目明显更好的战略 Harness 骨架，但仍不能据此确认 Agent 已具有稳定博弈、欺骗和反欺骗能力。

## 2. Findings

### P1：自己的公开发言会被重复投影并重复写入 Public Claims

当前存在两条同时生效的写入路径：

1. 当前玩家完成公开动作后，`GameOrchestrator` 立即把该动作按 `sourceEventSequence` 组装为 `PUBLIC_STATEMENT`，追加到自己的 `publicClaims`。
2. 本次 `MemoryUpdate.observedThroughSequence` 来自动作发生前构建的 Observation Batch，因此不会包含刚追加的 `PLAYER_ACTION` Sequence。
3. 玩家下一次行动时，`PlayerObservationProjector` 会再次把该 `PLAYER_ACTION` 放入 Observation Delta。
4. `LlmPlayerController.toCoreMemoryUpdate()` 又会把该事件转换为 `publicClaimsToAdd`。
5. `PlayerMemoryState.appendBounded()` 只做追加和截断，没有按 Sequence 去重。

结果不仅是存储层重复。在下一次模型调用发生时：

- 历史 `memory.publicClaims` 已经包含主机立即写入的该发言；
- 当前 `observationDelta` 又包含同一个 `PLAYER_ACTION`；
- 模型会在同一 Prompt 中看到同一句话两次；
- 本回合提交后，两种不同结构但相同 Sequence 的 Claim 都会留在 Memory 中。

这违反了设计文档中“增量事件解释状态变化”和“宿主确定性记录事实”的预期。重复证据可能被模型误当作多次陈述或额外佐证，也会让最多 120 条的 `publicClaims` 和送模时最多 40 条的窗口更快被自己的重复发言占满。

证据：

- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:403-409`
- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:462-482`
- `avalon-runtime/src/main/java/com/example/avalon/runtime/service/PlayerObservationProjector.java:18-35`
- `avalon-agent/src/main/java/com/example/avalon/agent/controller/LlmPlayerController.java:102-127`
- `avalon-core/src/main/java/com/example/avalon/core/player/memory/PlayerMemoryState.java:85-86,133-138`

建议将公开事件的正式记录收敛为单一、幂等路径。无论选择“动作接受后立即写入”还是“下一次 Observation 统一写入”，都应以 `sourceEventSequence`（并结合 actor/type）作为稳定身份去重。若立即写入并同步推进游标，必须证明从 Context 构建到动作落盘之间不会跳过其他可见事件；更稳妥的做法是让 `PlayerMemoryState` 对事件型 Facts/Claims 提供显式幂等合并。

### P1：不确定词仍会放行同一子句中的确定性私有身份断言

校验器仍使用以下规则：只要整个子句包含任意不确定词，就跳过该子句的全部身份断言检查。

例如，不使用当前分隔符拆句时，下面的发言可以整体绕过：

```text
P2 可能是梅林而 P3 就是莫甘娜
如果你问我 P3 就是刺客
我猜 P2 是梅林但 P4 就是莫甘娜
```

这些文本虽然包含“可能”“如果”或“猜”，但后半段仍是确定性断言。当前实现没有把不确定性限定到具体的 player-role assertion，而是把它当作整句豁免标记。

此外，校验本质上是有限别名和有限句式的正则防线。诸如“P3 必然属于邪恶阵营”“P3 的身份不会是其他角色”等表达不在当前 `就是/是/为 + roleAlias` 模式内。正则可以作为明显泄漏的防线，但不能被当作“私有知识一定不会通过公开表达泄漏”的完整证明。

证据：`avalon-agent/src/main/java/com/example/avalon/agent/service/PrivateKnowledgeExpressionValidator.java:45-56,84-99,127-139`。

建议至少把不确定性判断绑定到单个断言的局部范围，而不是整句 `continue`。更长期应将公开表达约束改为“可公开 Evidence 与声明强度”的结构化校验：模型若作出高置信身份判断，必须引用足以公开支持该判断的事件，而不是仅扫描敏感词。

### P2：Commitment 仍不是可维护的结构化状态

本轮已经避免把所有发言都当作承诺，这是有效修复；但当前实现仍将 `DECLARE_VOTE_INTENT` 和 `REVISE_POSITION` 对应的整条 `PUBLIC_STATEMENT` 序列化为 JSON 字符串，追加到 `List<String> commitments`。

剩余问题包括：

- `REVISE_POSITION` 只会新增一条 `status=ACTIVE` 的记录，不会把被修正的旧承诺标记为 `REVISED`、`WITHDRAWN` 或建立 supersedes 关系。
- `REVISE_POSITION` 是“修正立场”的 Speech Act，不保证文本一定包含未来行为约束，仍可能被误分类为 Commitment。
- `status` 虽写入了 `ACTIVE`，但没有任何状态迁移逻辑，因此目前只是静态标签。
- Commitments 是 JSON 字符串，查询、比较和更新都需要再次反序列化，字段契约无法由类型系统保证。
- `strategyState.publicCommitments` 仍由模型自由返回，而宿主权威 `memory.commitments` 是另一份数据，存在两个可能不一致的承诺来源。
- Prompt 仍要求模型输出 `commitmentsToAdd`，但主机合并时会完全丢弃模型提供的该列表，输出契约与实际接受语义不一致。

证据：

- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:468-505`
- `avalon-core/src/main/java/com/example/avalon/core/player/memory/MemoryUpdate.java:6-19`
- `avalon-core/src/main/java/com/example/avalon/core/player/memory/PlayerMemoryState.java:20,82`
- `avalon-agent/src/main/java/com/example/avalon/agent/service/PromptBuilder.java:78-87`
- `avalon-agent/src/main/java/com/example/avalon/agent/strategy/RoleStrategyPlanner.java:23-27`

建议新增强类型 `PublicCommitment`，至少包含：`actorPlayerId`、`sourceEventSequence`、`commitmentType`、`subject/targets`、`condition`、`position`、`status`、`supersedesSequence`。宿主从已接受动作确定性生成和更新该状态；`strategyState` 只保留模型的策略解释，不再复制权威承诺列表。

### P2：主机生成的 Public Statement 缺少明确 Actor，且与 Observation Claim Schema 不一致

主机立即写入的 `PUBLIC_STATEMENT` 包含 Sequence、Round、Speech Act、Statement、Targets 和 Status，但没有 `actorPlayerId`。下一回合由 Observation 生成的同一 Claim 则包含 `actorPlayerId`、`eventType`、`facts` 和 `utterance`。

这导致同一种公开事实存在两套结构：

- 主机即时结构：`statement/targets/status/sourceEventSequence`
- Observation 结构：`actorPlayerId/eventType/facts/utterance/sequence`

即使完成 Sequence 去重，后续工具也必须猜测字段和 Actor。当前 Memory 是玩家私有作用域并不能替代事件 Actor，因为 `publicClaims` 同时保存所有玩家的发言；数据项本身应可独立归因。

证据：

- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:485-498`
- `avalon-agent/src/main/java/com/example/avalon/agent/controller/LlmPlayerController.java:104-112`

建议定义统一 `PublicClaimRecord`，所有来源都通过同一投影器生成，并将 `actorPlayerId + sourceEventSequence` 作为必填字段。

## 3. 已确认修复

### 3.1 Observation 中其他玩家的公开 Claim 不再丢失

`hostPublicClaims` 现在从 `new ArrayList<>(update.publicClaimsToAdd())` 开始，再追加当前已接受发言。上一轮“游标推进但 Claim 被替换掉”的永久丢失问题已修复。

### 3.2 私有知识校验使用最终公开动作

`ValidationRetryPolicy` 先解析 `PlayerAction`，再把该 Action 传给 `PrivateKnowledgeExpressionValidator`。当最终动作是 `PublicSpeechAction` 时，校验器使用 `speechText()`，不再依赖可能为空的顶层 `AgentTurnResult.publicSpeech`。

### 3.3 精确身份校验不再被空候选列表整体跳过

`candidateKnowledge.isEmpty()` 的提前返回已删除，`validateExactKnowledgeDisclosure()` 会独立执行。该项修复了上一轮指出的控制流缺陷；不确定词和表达模式覆盖问题见本报告 P1。

### 3.4 普通发言不再全部污染 Commitments

QUESTION、ANSWER、CHALLENGE_CONSISTENCY、STATE_OPINION、LEADER_SUMMARY 等不再自动进入 `commitments`。宿主也不再接受模型任意上报的 `commitmentsToAdd` 作为正式承诺。承诺范围误分类的直接问题已修复，但状态模型仍未完成。

### 3.5 Strategy State 不再承载临时模型 Claim/Commitment

上一轮新增的 `modelCommitments`、`modelPublicClaims` 已删除，避免继续把不同生命周期的数据塞入自由 Map。

### 3.6 前几轮修复未发现回归

- Communication Plan 的公开文本和 Speech Act 继续与最终 Action 一致。
- Merlin `exposureRisk` 继续要求为 `[0,1]` 内有限数值。
- 欺骗意图白名单继续由 `RoleStrategyPolicy` 统一提供。
- 非公开动作继续不要求 Communication Speech Act。
- 任务结果事件继续携带 `teamPlayerIds`，noop 优先按事件中的任务队伍归因。

## 4. 对“是否已经具备稳定博弈能力”的判断

当前版本相较前身项目已经解决了最致命的架构问题：Agent 只能获得自己的 Private View、自己的 Memory 和公共事件投影，没有发现读取其他 Agent 私有 Memory 的路径。公开主张与世界事实也已经有基本分类，角色策略、欺骗白名单、跨回合 Belief/Strategy、讨论 Speech Act 和证据引用均已进入 Harness。

这些机制说明项目不再是单纯的“进度总结式 Agent”。但是，稳定博弈能力仍不能从当前代码静态推出，原因包括：

1. `StrategicBehaviorEvaluator` 只在 testkit/测试中调用，没有形成每次真实 Provider 对局的正式验收和回归门禁。
2. 现有指标主要验证结构存在、引用存在和协议完成，仍不能判断质疑是否有效、证据方向是否合理、欺骗是否影响受众、队伍选择是否提高胜率。
3. 设计中的 claim history、vote history、contradiction detection、team outcome comparison、commitment query 等确定性工具仍未实现。
4. 讨论调度仍是固定 Opening、最多两个 Challenge、Targeted Response、Leader Summary，不会按争议强度和信息价值动态调度。
5. Belief 仍是一维“邪恶阵营概率”，无法表达完整角色候选分布以及角色间互斥约束。
6. 模型 Profile 当前全部 `enabled: false`，没有真实 Provider、多 seed、座位轮换、角色轮换和 baseline 对照结果。
7. 当前 Claim 重复与 Commitment 状态问题会直接削弱跨回合矛盾识别和叙事一致性。

因此更准确的结论是：**当前 Harness 已经为博弈提供了必要但不充分的基础设施；它显著提高了 Agent 能够博弈的上限，但尚未用行为证据证明 Agent 会稳定利用这些能力。**

## 5. 建议优先级

1. 修复 Public Claim 的单一来源和幂等合并，保证每个公开事件在每个 Agent Memory 中至多一条权威记录。
2. 修复私有知识校验的整句不确定词豁免；同时明确该正则只是一层防线，不是信息泄漏的完整证明。
3. 将 Commitment 升级为强类型、可修正、可撤回、可兑现的状态，并移除 `strategyState.publicCommitments` 与正式 Memory 的双源问题。
4. 统一 Public Claim Schema，补齐 Actor 和稳定事件身份。
5. 将真实 Provider 多局评测接入可重复的验收流程，至少按同模型、同 seed、座位轮换与 baseline 对照。
6. 再实现确定性战略工具和动态讨论调度，避免继续把复杂比较全部压给单次 Prompt。
