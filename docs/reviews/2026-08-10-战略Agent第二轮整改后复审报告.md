# 战略 Agent 第二轮整改后复审报告

复审日期：2026-08-10  
评审对象：当前工作区相对 `f09e974` 的最新整改。  
评审基线：`2026-08-10-战略Agent整改后复审报告.md`。

## 1. 结论

上一轮复审提出的五个具体问题中，四项已经正确修复：

- Communication Plan 现在基于解析后的最终 `PublicSpeechAction` 校验，顶层 `publicSpeech` 回退绕过已关闭。
- `communicationPlan.speechAct` 会与最终公开动作的 Speech Act 比较。
- Merlin `exposureRisk` 已要求为 `[0,1]` 内的有限数值。
- 角色欺骗白名单已集中到 `RoleStrategyPolicy`，Prompt 投影和宿主校验复用同一来源。
- 非公开动作不再强制要求 `communicationPlan.speechAct`。

公开承诺也开始与已接受的 `PLAYER_ACTION` Event Sequence 绑定，这是正确方向。

但是，本轮承诺重构引入了一个新的 P1 Memory 回归：**Agent 本回合观察到的其他玩家公开 Claim 会在提交 Memory 时被替换掉，而观察游标仍继续前进，导致这些 Claim 后续不再进入正式 Memory。** 此外，私有知识表达校验仍检查 Gateway 原始字段而不是最终动作，信息表达边界依然存在绕过。

因此本轮不能判定全部整改完成。

## 2. 发现

### P1：承诺增强会丢弃本回合已观察到的其他玩家 Public Claims

`LlmPlayerController.toCoreMemoryUpdate()` 会把当前 Observation Delta 中的公开发言确定性整理到 `MemoryUpdate.publicClaimsToAdd`。这原本是“宿主记录公开事实”的正式路径。

新的 `enrichPublicCommitment()` 读取该列表后：

1. 把它放入 `strategyState.modelPublicClaims`；
2. 创建一个只包含当前玩家本次发言的 `hostPublicClaims`；
3. 构造新 `MemoryUpdate` 时，用 `hostPublicClaims` 替换原 `update.publicClaimsToAdd()`。

结果是：当前增量中其他玩家的公开发言不会进入 `PlayerMemoryState.publicClaims`。与此同时，`observedThroughSequence` 仍更新到当前观察尾部，下一轮不会再次投影这些事件，因此它们会从正式跨回合认知中永久缺失。

这会直接削弱跨回合矛盾识别、承诺对比和社会推理，属于高影响认知回归。

证据：

- `avalon-agent/src/main/java/com/example/avalon/agent/controller/LlmPlayerController.java:102-129`
- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:467-486`
- `avalon-core/src/main/java/com/example/avalon/core/player/memory/PlayerMemoryState.java:81-108`

正确方向应是保留 `update.publicClaimsToAdd()`，再追加当前已接受的公开发言，而不是替换。这里的 `update.publicClaimsToAdd()` 已经是宿主从 Observation 生成的数据，并不是模型自报内容，不应命名为 `modelPublicClaims`。

### P1：私有知识表达校验仍可通过 Action Speech 绕过

执行顺序现在是：

```text
parse final PlayerAction
-> validate strategic contract using final action
-> validate private knowledge using raw AgentTurnResult
```

`PrivateKnowledgeExpressionValidator` 仍只检查：

- `result.privateThought`
- `result.publicSpeech`
- `result.auditReason`

它没有检查解析后的 `PublicSpeechAction.speechText`。当模型令顶层 `publicSpeech = null`，并把实际文本放在 `action.speechText` 时：

- `ResponseParser` 会采用 `action.speechText` 作为正式公开发言；
- 新的 Communication Plan 校验可以正常通过；
- 私有知识表达校验看到的仍是 null，因此不会扫描实际公开文本。

Percival 等角色可以利用该路径把候选身份说成确定事实；未来任何拥有 `exactRoleId` 私有知识的角色也可能绕过公开表达限制。

此外，`PrivateKnowledgeExpressionValidator.validate()` 在 `candidateKnowledge.isEmpty()` 时直接返回，导致只拥有精确私有角色知识、但没有歧义候选的场景连 `validateExactKnowledgeDisclosure()` 都不会执行。

证据：

- `avalon-agent/src/main/java/com/example/avalon/agent/service/ValidationRetryPolicy.java:40-47`
- `avalon-agent/src/main/java/com/example/avalon/agent/service/ResponseParser.java:31-46`
- `avalon-agent/src/main/java/com/example/avalon/agent/service/PrivateKnowledgeExpressionValidator.java:23-38`

建议让私有知识表达校验接收解析后的 `PlayerAction`，并以 `PublicSpeechAction.speechText` 为唯一权威公开文本。

### P2：所有公开发言都被写入 Commitments，语义仍不准确

新的实现不再只处理两个 Speech Act，而是把每一次 `PublicSpeechAction` 都序列化后写入 `commitments`。这解决了覆盖不足，但把以下内容也当成了承诺：

- QUESTION
- ANSWER
- CHALLENGE_CONSISTENCY
- STATE_OPINION
- LEADER_SUMMARY

这些是公开陈述或互动行为，不一定包含未来承诺。虽然记录对象的 `type` 是 `PUBLIC_STATEMENT`，最终却仍进入 `PlayerMemoryState.commitments` 字符串列表。

后续 `get_my_public_commitments` 或 Cover Story 一致性分析如果把整个列表视为承诺，会产生大量误报。建议把 `publicStatements/publicClaims` 与真正的 `publicCommitments` 分开；只有结构化的投票意图、条件承诺、支持/反对约束和立场修正才进入 Commitments。

证据：`avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:474-502`。

### P2：模型建议被塞入 Strategy State，仍缺少稳定的作用域模型

模型返回的 `commitmentsToAdd` 被移动到 `strategyState.modelCommitments`。这种做法避免了直接污染宿主承诺列表，但仍存在两个问题：

- Strategy State 每回合整体替换，旧的模型建议不会自然累计或具有状态；
- `modelCommitments` 与正式策略字段混在同一个自由 Map 中，Memory Policy 无法独立限制其数量、来源和生命周期。

如果需要保留模型建议，应使用明确的 `proposedCommitments` 私有 Draft，并在动作接受后由宿主映射到公开事件；不要把它临时塞进正式 Strategy Map。

## 3. 已确认修复

### 3.1 Communication Plan 现在以最终动作作为权威输入

`ResponseParser.parse()` 已提前执行，`validateStrategyContract()` 接收解析后的 `PlayerAction`。实际公开文本和 Speech Act 均与 Communication Plan 对比，上一轮指出的顶层字段绕过已经修复。

### 3.2 Merlin exposureRisk 已有有效数值边界

当前要求 `exposureRisk` 为 Number、有限值且处于 `[0,1]`。null、文本、NaN、Infinity 和越界数值均会被拒绝。

该项完成了字段合法性约束；是否根据证据合理变化仍属于更高阶行为验收。

### 3.3 欺骗策略白名单已单一来源

新增 `RoleStrategyPolicy`，`RoleStrategyPlanner` 和 `ValidationRetryPolicy` 共同使用其 `permittedDeceptionIntents()`。双份硬编码问题已解决。

### 3.4 非公开阶段不再强制 Communication Speech Act

只有最终动作是 `PublicSpeechAction` 时才要求 Communication Plan 的公开文本和 Speech Act。TEAM_PROPOSAL、TEAM_VOTE、MISSION_ACTION 和 ASSASSINATION 不再被迫填写无意义的公开表达字段。

### 3.5 任务结果队伍归因保持正确

`MISSION_FAILED`/`MISSION_SUCCESS` 仍携带 `teamPlayerIds`，noop 仍优先使用事件中的任务队伍。没有发现该修复发生回归，也没有新增任务票对应关系泄漏。

## 4. 原综合报告中仍未覆盖的问题

以下问题本轮仍未修改：

1. `StrategicBehaviorEvaluator` 未进入正式对局质量链路，指标仍可被形式字段刷过。
2. 没有 claim/vote/contradiction/team outcome 等确定性战略工具。
3. 讨论调度仍是固定 Opening、两个 Challenge、Response、Leader Summary。
4. 私有知识表达校验的整句不确定词绕过仍存在。
5. 缺少版本化、可对照的 Agent 人格 Profile。
6. Belief 仍是一维邪恶概率，不能表达完整角色候选关系。
7. 模型 Profile 全部禁用，尚无真实 Provider、多 seed、角色轮换的行为验收。

## 6. 最终判定

上一轮提出的 Communication Plan、Merlin 风险值、欺骗白名单复用和阶段裁剪问题已经处理正确，说明战略契约正在持续下沉到宿主。

当前应优先修复两个 P1：

1. `enrichPublicCommitment()` 必须保留本回合 Observation 产生的 `publicClaimsToAdd`，避免跨回合公开发言永久丢失。
2. 私有知识表达校验必须检查解析后的最终 `PublicSpeechAction`，并移除“没有候选知识就跳过精确知识校验”的提前返回。

在这两个问题修复前，信息差读取隔离仍然基本成立，但公开表达防泄漏和跨回合社会记忆不能判定通过。
