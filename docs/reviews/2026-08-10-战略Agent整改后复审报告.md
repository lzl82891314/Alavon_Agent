## 1. 复审结论

本轮整改有效完成了一个问题、部分完成了三个问题：

| 原问题 | 当前状态 | 复审结论 |
| --- | --- | --- |
| noop 无法把任务失败归因到任务成员 | 已修复 | 任务结果事件携带 `teamPlayerIds`，noop 从事件读取队伍，不再依赖已清空的当前快照 |
| deception intent 仅靠 Prompt | 部分修复 | 宿主已经按角色拒绝越权 intent，但策略白名单重复定义，Cover Story 和欺骗连续性仍未校验 |
| 战略字段只要求有 MemoryUpdate | 部分修复 | 已要求 mode、objective、communication speechAct，并检查部分公开文本一致性；仍存在动作字段绕过 |
| 公开承诺依赖模型 | 部分修复 | 宿主开始从部分 Speech Act 追加承诺，但覆盖范围很窄，且仍与模型自报承诺混存 |
| 战略评估器可刷过/未进入运行时 | 未修改 | 仍不能作为真实博弈能力证明 |
| 战略工具、动态讨论、Agent 差异化、完整 Belief | 未修改 | 仍属于后续能力缺口 |

当前版本比整改前更接近“宿主执行战略契约”，但仍不能宣称战略闭环完成，也不能据此确认真实 Agent 已稳定具备博弈能力。

## 2. 仍需处理的发现

### P1：Communication Plan 与最终公开动作仍可不一致

`validateStrategyContract()` 只在 `AgentTurnResult.publicSpeech` 非空时，将它与 `communicationPlan.publicMessage` 比较。但 `ResponseParser` 在顶层 `publicSpeech` 为空时，会回退使用 `action.speechText` 作为实际公开发言。

模型可以返回：

```json
{
  "publicSpeech": null,
  "memoryUpdate": {
    "communicationPlan": {
      "speechAct": "ANSWER",
      "publicMessage": "计划中的回答"
    }
  },
  "action": {
    "actionType": "PUBLIC_SPEECH",
    "speechText": "实际公开的另一段话",
    "speechAct": "REVISE_POSITION"
  }
}
```

该结果会跳过 `publicMessage` 比较；最终公开文本来自 `action.speechText`。同时，当前校验也没有比较 `communicationPlan.speechAct` 与 `action.speechAct`。

因此新增校验还不能保证“私有沟通计划 -> 最终公开表达”的一致性，这仍是综合报告中战略字段自报问题的实质绕过路径。

证据：

- `avalon-agent/src/main/java/com/example/avalon/agent/service/ValidationRetryPolicy.java:107-123`
- `avalon-agent/src/main/java/com/example/avalon/agent/service/ResponseParser.java:31-46`

建议在解析出最终 `PlayerAction` 后验证 Communication Plan，或统一以解析后的 `PublicSpeechAction` 为唯一权威值，不要分别比较 Gateway DTO 和 Action JSON。

### P1：宿主承诺记录只覆盖两个实际可达 Speech Act

`enrichPublicCommitment()` 允许以下四种 Speech Act：

- `DECLARE_VOTE_INTENT`
- `CLAIM_SUPPORT`
- `CLAIM_OPPOSE`
- `REVISE_POSITION`

但当前讨论协议从未允许 `CLAIM_SUPPORT` 和 `CLAIM_OPPOSE`。实际可达的只有 `DECLARE_VOTE_INTENT` 和 `REVISE_POSITION`。Opening 的 `STATE_OPINION`、`PROPOSE_TEST`，以及 `LEADER_SUMMARY` 即使包含明确承诺，也不会被宿主记录。

此外，宿主只是把整段话追加为字符串，并继续保留模型提供的全部 `commitmentsToAdd`。这使权威承诺和模型自报承诺无法区分：

- 模型仍可添加从未公开说过的承诺；
- 宿主无法识别承诺对应的公开事件 Sequence；
- `REVISE_POSITION` 会被整体视为承诺，即使文本没有未来约束；
- 相同承诺可能由模型和宿主重复写入。

所以“公开承诺由宿主确定性维护”仍只能判定为部分完成。

证据：

- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:458-477`
- `avalon-runtime/src/main/java/com/example/avalon/runtime/model/GameRuntimeState.java:320-330`

建议将宿主承诺建模为结构化记录，至少包含 `sourceEventSequence`、`speechAct`、`subject/target`、`commitmentType`、`condition` 和 `status`；模型建议与宿主事实应使用不同字段。

### P2：Merlin exposureRisk 只检查键存在，不检查有效值

当前 Merlin 校验使用 `strategy.containsKey("exposureRisk")`。以下值都可以通过：

- `null`
- 空字符串
- 任意文本
- 负数或大于 1 的数

因此它证明不了 Merlin 真正在跟踪暴露风险。建议要求有限数值并限制在 `[0,1]`，同时对无新证据时的变化幅度做约束。

证据：`avalon-agent/src/main/java/com/example/avalon/agent/service/ValidationRetryPolicy.java:124-126`。

### P2：角色欺骗白名单存在双份硬编码

`RoleStrategyPlanner` 和 `ValidationRetryPolicy` 分别维护相同的角色欺骗列表。一旦新增角色或修改策略，只改其中一处会出现“Prompt 允许但宿主拒绝”或“Prompt 禁止但宿主接受”。

当前两份列表内容一致，所以不是即时行为错误；但这是高概率演进回归点。建议由单一强类型 `RoleStrategyPolicy` 同时提供 Prompt 投影和宿主校验。

### P2：非公开动作也被要求填写 communicationPlan.speechAct

当前 `validateStrategyContract()` 对 TEAM_PROPOSAL、TEAM_VOTE、MISSION_ACTION 和 ASSASSINATION 同样要求非空 `communicationPlan.speechAct`。这些阶段没有公开发言，强制填写 `STATE_OPINION` 等值只会制造无意义字段，并提高真实模型格式失败概率。

设计文档明确实际 Schema 应按阶段裁剪。建议只在 `PUBLIC_SPEECH` 阶段要求 Communication Plan 的公开表达字段，其他阶段要求与动作相关的战略字段。

## 3. 已确认修复的内容

### 3.1 任务结果归因已闭环

`resolveMission()` 在清空队伍前读取 `currentMissionTeam`，并把玩家 ID 写入 `MISSION_FAILED`/`MISSION_SUCCESS` 的 `teamPlayerIds`。公开队伍本来就是已公开事实，因此没有新增私有信息泄漏。

`NoopAgentGateway` 随后优先从任务结果事件读取队伍；旧事件缺少该字段时才回退当前快照。这修复了任务结算后 `currentTeamPlayerIds` 为空导致的信念不更新问题，也让 `evidenceMentionsPlayer()` 能直接把任务结果绑定到队伍成员。

证据：

- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:318-335`
- `avalon-agent/src/main/java/com/example/avalon/agent/gateway/NoopAgentGateway.java:51-57,200-208`

### 3.2 角色欺骗 intent 已有第一层宿主边界

`ValidationRetryPolicy` 现在会按角色拒绝不允许的 intent。好人不能再仅靠模型自报 `BUILD_FALSE_CREDIBILITY`，Oberon、Merlin、Percival 等角色也各自受白名单限制。

该项解决的是“角色是否有权使用某种欺骗”，没有解决欺骗是否合理、Cover Story 是否连续或是否有效影响受众。

### 3.3 基础战略字段开始受到宿主校验

`strategyState.mode`、`strategyState.objective` 和 `communicationPlan.speechAct` 现在必须非空，显著好于只要求 `memoryUpdate` 存在。Merlin 也开始被要求提供 `exposureRisk` 字段。

这能淘汰完全空的战略 Map，但仍不能淘汰固定模板字段或语义无关的战略内容。

## 4. 未被本轮修改覆盖的综合报告问题

以下问题仍保持原判定：

1. `StrategicBehaviorEvaluator` 仍位于 testkit，没有进入正式对局质量记录或验收链路。
2. `meetsStrategicGate()` 仍只统计字段存在、事件引用和次数，无法验证策略方向和欺骗效果。
3. 没有 claim/vote/contradiction/team outcome 等确定性战略工具。
4. 讨论仍固定为 Opening、两个 Challenge、Response、Leader Summary，缺少基于矛盾和信息增益的动态调度。
5. 私有知识表达校验仍可被同一子句中的不确定词绕过。
6. 同预设 Agent 仍共享相同 cognition/communication/deception 参数，没有版本化人格 Profile。
7. Belief 仍是一维邪恶概率，不能表达 Percival 和 Assassin 所需的多角色候选。
8. 当前模型 Profile 全部禁用，尚无真实 Provider、多 seed、角色轮换的行为验收结果。

## 6. 最终判定

本轮整改不是形式性修改：任务失败证据现在能正确关联队伍，角色欺骗权限也确实进入了宿主校验，战略空字段和部分沟通不一致会被拒绝。

但当前仍存在两个需要优先完成的 P1：

1. 以解析后的最终动作验证 Communication Plan，消除顶层 `publicSpeech` 回退绕过和 Speech Act 不一致。
2. 将公开承诺改为与事件绑定的宿主结构化事实，停止把权威承诺与模型自报字符串混为同一列表。

完成这两项后，战略契约才算从“部分下沉”接近“正式闭环”。即使如此，真实博弈能力仍需通过行为评估和真实 Provider 对局证明。
