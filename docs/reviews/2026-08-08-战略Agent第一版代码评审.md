# 战略 Agent 第一版代码评审

评审日期：2026-08-08

评审对象：`D:\Code\Alavon_Agent` 当前战略 Harness 主链路。

## 1. 最新结论

本轮已修复此前阻断信息差安全验收的三个 P0/P1 问题：

1. 梅林和邪恶同伴现在只获得规则允许的阵营信息，不再获得其他玩家的精确角色。
2. 派西维尔的 Merlin/Morgana 候选不再携带真实阵营，无法借 `camp` 绕过身份歧义。
3. Coordinator 和 `GameOrchestrator.step/runToEnd` 均在投票、任务阶段冻结所有玩家上下文，收齐动作后统一揭示。

信念更新和长局 Memory 也已从 Prompt 建议升级为宿主约束：无证据变化、单次最大变化、合法玩家集合、私有已知阵营一致性均会校验；正式送模 Memory 有固定字符预算和确定性压缩。

因此，针对已确认的精确角色泄漏、顺序票型泄漏和跨玩家 Memory 风险，当前版本可以通过代码级信息差安全验收。尚不能宣称真实模型已经稳定具备高水平质疑、欺骗和伪装能力，因为当前环境没有启用的模型档案或 Provider 凭据，真实多模型评测尚未执行。

本轮增量复核确认上述修复已进入正式代码路径，但“信念更新已升级为宿主约束”只能有限成立：宿主能限制变化幅度，却尚未把证据绑定到具体玩家或具体信念。信息差安全基本达标，战略行为质量仍未完成验收。

最新一轮已进一步修复这两个残余结构问题：MemoryUpdate 增加逐玩家 `beliefEvidenceReferences`，管理员审计和私有视图改为 capability-gated 的 `AdminGameInspectionService`。当前评审不再把“全局 Evidence Ref”或“无授权审计接口”列为已存在缺陷，但仍保留相应设计边界和验证要求。

## 2. 信息差修复

### 2.1 角色知识矩阵

`RoleKnowledgeResolver` 现在区分三种语义：

| 规则 | `exactRoleId` | `camp` | `candidateRoleIds` |
| --- | --- | --- | --- |
| `SEE_PLAYERS_BY_CAMP` | `null` | 目标阵营 | 该阵营允许的候选角色 |
| `SEE_ALLIED_EVIL_PLAYERS` | `null` | `EVIL` | 非排除邪恶角色集合 |
| `SEE_PLAYERS_BY_ROLE` | 精确角色 | 对应阵营 | 精确角色 |
| `SEE_ROLE_AMBIGUITY` | `null` | `null` | 配置的歧义候选集合 |

这保证：

- 梅林知道哪些玩家是可见邪恶，但不知道谁是刺客或莫甘娜。
- 刺客、莫甘娜、莫德雷德知道非奥伯伦邪恶同伴，但不知道同伴的具体角色。
- 派西维尔看到 Merlin/Morgana 两名候选，但不能通过阵营字段直接区分。
- 只有规则明确使用 `SEE_PLAYERS_BY_ROLE` 时才允许精确身份。

### 2.2 同时秘密投票和任务选择

所有自动执行路径现在采用相同流程：

```text
build every required PlayerTurnContext from one state version
-> invoke controllers with frozen contexts
-> collect all proposed actions
-> validate the complete batch
-> commit actions
-> reveal aggregate result
```

后行动的 Controller 不会看到本批次较早生成的票型或任务选择。旧的逐票 `TEAM_VOTE_CAST` 顺序路径已从 `step()` 移除。

### 2.3 事件默认私有

事件可见性已集中到 `GameEventVisibilityPolicy`。Observation、持久化、HTTP Event 和 Replay 复用同一显式公开白名单；未知事件默认 `PRIVATE`，不再依赖三个分散的私有黑名单。

## 3. 信念更新约束

`ValidationRetryPolicy` 对 `roleBeliefs` 实施以下宿主规则：

- 目标必须是本局存在的玩家。
- 概率必须位于 `[0,1]`。
- 首次未知先验相对 `0.5` 的偏移不得超过 `0.15`。
- 已有信念在无 Evidence Ref 时单次变化不得超过 `0.05`。
- 有可见 Evidence Ref 时单次变化不得超过 `0.25`。
- 本人阵营和私有知识明确看到的阵营必须保持 `GOOD=0`、`EVIL=1`，无需伪造公开证据。
- Evidence Sequence 必须属于当前可见增量或该玩家自己的保留历史。

超出限制的输出不会写入 Memory，而是进入有限修复重试。

当前实现已增加逐玩家 Evidence Binding：每个有变化的玩家都必须提供自己的引用，引用必须可见且事件 payload/actor/mentions 中包含该玩家。全局 `evidenceReferences` 仍保留用于一般记忆和审计，不再作为 belief delta 的放宽条件。

仍有一个需要产品确认的边界：`evidenceMentionsPlayer` 对 `MISSION_FAILED`、`MISSION_SUCCESS` 等 `SYSTEM` 事件要求事件事实中出现玩家 ID；这会让“某个队伍任务失败”无法直接作为队伍成员各自的证据，除非模型同时引用包含队伍成员的 `TEAM_PROPOSED` 事件。当前实现偏保守，安全上没有放大权限，但可能造成合法的信念更新被拒绝。

## 4. Memory 预算与压缩

正式 Memory 分成存储边界和送模边界：

- `observations` 最多 80 条，每条最多 500 字符。
- `commitments` 最多 40 条，每条最多 500 字符。
- `inferredFacts` 最多 80 条，每条最多 500 字符。
- `worldFacts`、`publicClaims` 各最多 120 条。
- `lastSummary` 最多 2,000 字符。
- 送模前 `MemoryContextProjector` 默认限制为 12,000 字符。
- 送模窗口优先保留当前信念、策略、沟通计划、最近承诺、最近事实和 Claim。
- 嵌套 Map/List、长字符串和旧条目会确定性压缩。
- `contextWindow` 记录字符预算、估算 Token、保留条目数和是否发生压缩。

这避免长局把完整历史 Memory 重复塞入 Prompt。当前 Token 数使用字符估算而非 Provider 专用 tokenizer；它是稳定的宿主上限，但不是精确计费 Token。

## 5. 行为评测

新增 `StrategicBehaviorEvaluator`，直接基于正式 Event/Audit 统计：

- Challenge 数量和质询点名率。
- Targeted Response 数量和质疑事件引用率。
- 信念修正次数和 Evidence 支撑率。
- 非 `NONE` 欺骗意图或 Cover Story 出现次数。
- 校验失败次数。

`meetsStructuralGate()` 当前要求存在 Challenge 和 Targeted Response、二者协议命中率至少 95%、且没有校验失败。离线完整对局和构造审计样本均使用同一评测器。

当前门槛已升级为 `meetsStrategicGate()`：要求至少一次信念修正、证据支撑率至少 90%、邪恶 Agent 出现时至少有一个欺骗计划、以及公开叙事一致性至少 90%。这是对“机械流程 Agent”的明显改进。

但它仍是结构/行为代理指标，不是策略正确性证明：

- 只要模型产生一次有证据的概率变化，就能满足 belief revision 条件，未检查变化方向是否改善阵营决策。
- `deceptionPlanCount > 0` 只检查字段存在，不检查欺骗是否收益正向、是否成功影响受众或是否与角色允许意图一致。
- `narrativeConsistencyRate` 对没有既有 Cover Story 的局面默认记为 1.0，样本很短时容易被少量事件“刷过”。
- 构造审计样本仍然只是评估器单元测试，不是真实 Provider、多 seed 或基线对照。

真实模型验收仍待执行。本机检查结果：

- `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`DEEPSEEK_API_KEY`、`GLM_API_KEY`、`MINIMAX_API_KEY` 均未配置。
- 五个模型 Profile 均为 `enabled: false`。

因此本报告不虚构真实模型胜率或行为指标。拿到凭据后，应至少运行 3 个模型、20 至 30 个 seed，并按角色比较战略 Harness 与简化基线。

## 6. 自动化验证范围

当前回归场景包括：

- Merlin 阵营视图不包含精确角色。
- 邪恶同伴视图不包含精确角色。
- Percival 候选不包含真实阵营。
- 直接 `step()` 的所有投票上下文具有相同观察游标且看不到本批次票型。
- 未知新事件默认不进入玩家观察。
- 无证据大幅信念变化被拒绝。
- 有证据但超过单次幅度的变化被拒绝。
- 有可见证据的有界变化被接受。
- 私有已知阵营可以固定为确定概率。
- Memory 压缩后不超过配置的字符预算并保留关键战略状态。
- 多轮讨论满足质询点名和定向回复引用门槛。
- 非法动作零事件、零 Memory 副作用。
- Snapshot 恢复保留讨论状态和观察游标。

## 7. 仍未完成的能力

本节原有条目记录的是本轮修复前的遗留项；其中逐信念 Evidence Binding、行为门槛和审计授权已在 8.1 完成，以下仍有效的外部验收项主要是实时模型行为和更高阶战略一致性分析。

以下项目不再是已知信息泄漏，但仍影响真实博弈上限：

1. 逐信念 Evidence Binding 和证据语义相关性验证。
2. Cover Story 与公开承诺的确定性冲突检测。
3. 时间线、投票历史、队伍组合和矛盾检测战略工具。
4. 根据事件量和不确定性触发的两阶段推理。
5. 真实 Provider 多模型、多 seed、按角色分层 A/B 评测。

### 7.1 管理审计隔离

该项已修复。`GameApplicationService` 不再暴露审计/私有视图查询；`AdminGameInspectionService` 要求 `AdminInspectionCapability`，而 capability 只由 `LocalConsoleAdminAccess` 持有并通过对象身份比较授权。当前仍应补充集成测试，确保未来新增 HTTP Controller 不接受用户可构造的 capability DTO。

## 8. 最终判定

### 8.1 本轮修复复核（2026-08-08）

本轮已完成上一节列出的三项代码整改：

1. `MemoryUpdate.beliefEvidenceReferences` 按玩家绑定证据；宿主校验每条引用的可见性，并要求事件 actor、facts 或 mentions 在结构上关联目标玩家。全局 `evidenceReferences` 仅作为整体策略依据，不能为多个玩家的信念变化背书。
2. `StrategicBehaviorEvaluator` 现在区分 `meetsProtocolGate()` 与 `meetsStrategicGate()`。战略门槛要求至少一次信念修正、逐信念证据支持率不低于 90%、邪恶 Agent 存在时必须出现欺骗计划，并检查 Cover Story 的跨回合连续性。`meetsStructuralGate()` 兼容保留但已委托严格战略门槛。
3. `GameApplicationService` 不再暴露审计和玩家私有视图。两者迁移至 `AdminGameInspectionService`，查询必须携带进程内不可伪造的管理员 capability；本地 Console 通过专用 capability provider 访问。

代码回归测试当前共 23 项，全部通过。该结果证明信息边界、证据绑定和评测门槛在宿主层生效，不等同于真实 LLM 已具备稳定博弈能力。真实 Provider、多模型、多 seed、分角色 A/B 评测仍是外部验收项；当前五个模型 Profile 均未启用且未配置对应 API Key。

- **是否仍会读取其他 Agent Memory？** 正式上下文中未发现该入口。
- **梅林或邪恶阵营是否还能看到其他玩家精确角色？** 不能，除非角色规则明确配置 `SEE_PLAYERS_BY_ROLE`。
- **后投票 Agent 是否还能看到前票？** 不能，所有正式自动路径均使用冻结批次。
- **信念是否还能无证据从 0.1 跳到 0.9？** 不能，宿主会拒绝并触发修复。
- **长局是否仍发送完整无限增长 Memory？** 不能，存储和送模两层均有上限。
- **是否已证明真实 LLM 稳定博弈？** 尚未。评测机制已落地，但真实 Provider 实验受当前配置和凭据阻塞。
- **当前行为门槛能否淘汰“机械流程 Agent”？** 基本能淘汰完全不更新信念、不生成欺骗计划或不维护叙事的输出，但不能证明策略方向正确或欺骗有效。
