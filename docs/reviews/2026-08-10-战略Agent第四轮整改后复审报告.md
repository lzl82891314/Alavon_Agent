# 战略 Agent 第四轮整改后复审报告

复审日期：2026-08-10  
评审对象：当前工作区相对《战略 Agent 第三轮整改后复审报告》的最新修改。  
评审范围：公开 Claim 幂等合并、私有知识表达校验、Commitment 状态迁移、战略输出契约。

## 1. 总结结论

本轮确实加入了三类有价值的修复：

- `PlayerMemoryState.appendBounded()` 会按 `sourceEventSequence/sequence` 去重，重复 Claim 不再永久堆积。
- 主机生成的即时 `PUBLIC_STATEMENT` 增加了 `actorPlayerId` 和 `eventType`。
- `REVISE_POSITION` 开始尝试把已有 ACTIVE 承诺标记为 `REVISED`，并支持同一事件序列的 Commitment 替换。

但本轮仍不能判定全部问题闭环：

1. 私有知识校验的连接词分句修复实际上没有生效，整句不确定词绕过仍可利用，因此该 P1 仍然存在。
2. Claim 去重只发生在 Memory 合并阶段。下一次模型调用时，同一个事件仍同时出现在 `memory.publicClaims` 和 `observationDelta`，模型仍会看到重复证据。
3. `REVISE_POSITION` 会把所有 ACTIVE 历史承诺一起改成 `REVISED`，而不是只修正与当前立场相关的承诺，可能破坏跨回合一致性分析。
4. 正式 Commitment 仍是 JSON 字符串，且 Prompt 要求的 `strategyState.publicCommitments` 在主机合并时被删除，输出契约与持久化状态不一致。

因此当前版本的私有信息隔离仍基本成立，Claim 的持久化完整性较上一轮有所改善，但战略认知闭环和承诺语义仍未达到可验收状态。它已经显著优于前身的“无脑信任、无信息差博弈”架构，但仍不能仅凭静态代码确认 Agent 会稳定欺骗、质疑和利用信息差。

## 2. Findings

### P1：不确定词分句修复顺序错误，整句绕过仍然存在

`clauses()` 当前先执行 `text.split(...)`，之后才执行：

```java
text = text.replaceAll("\\u4f46(?:\\u662f)?|\\u540c\\u65f6|\\u800c", "\\n");
```

但是替换发生在 `rawClauses` 创建之后，后续循环仍然遍历替换前的数组。因此 `但是`、`同时`、`而` 不会产生新的子句边界。

下面这类文本仍会作为一个整体进入 `isCertainMatch()`，并可能因前面的不确定词跳过后半段确定性断言：

```text
P2 可能是梅林而 P3 就是莫甘娜
如果你问我 P3 就是刺客
我猜 P2 是梅林但是 P4 就是莫甘娜
```

证据：`avalon-agent/src/main/java/com/example/avalon/agent/service/PrivateKnowledgeExpressionValidator.java:149-159`。

此外，当前局部不确定性检查只查看匹配开始位置之前的 16 个字符。对于 `P2可能是梅林`，不确定词位于 player alias 之后，不会被 `localContext` 捕获，反而会被当作确定性断言拒绝。这会造成合法的不确定表达被重试或失败。

证据：`avalon-agent/src/main/java/com/example/avalon/agent/service/PrivateKnowledgeExpressionValidator.java:126-135`。

建议先完成所有分句归一化，再执行 split；更稳妥的是解析“玩家 + 角色 + 断言强度”三元组，并只对该断言的局部范围判断不确定性，而不是使用固定字符窗口。

### P2：Claim 持久化去重已修复，但下一轮 Prompt 仍重复呈现同一事件

`appendBounded()` 现在能够在 Memory 合并时保留一份相同 Sequence 的 Claim，这是正确的幂等改进。但动作接受后主机会立即把当前发言写入 Memory，而 `lastObservedSequence` 仍然来自动作前的 Observation Batch。下一回合：

- `memory.publicClaims` 已包含主机即时生成的 Claim；
- `observationDelta` 又包含同一个 `PLAYER_ACTION`；
- `PromptBuilder` 同时渲染两者。

因此本轮解决的是“永久重复存储”，没有解决“决策输入重复证据”。单个事件仍可能在模型上下文中出现两次，影响证据权重和上下文预算。

证据：

- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:454-489`
- `avalon-runtime/src/main/java/com/example/avalon/runtime/service/PlayerObservationProjector.java:18-35`
- `avalon-agent/src/main/java/com/example/avalon/agent/service/PromptBuilder.java:38-45`

建议选择唯一权威路径：要么动作接受后推进该玩家游标并确保没有跳过中间事件，要么不立即写入普通 Public Claim、由下一次 Observation 统一写入。无论采用哪种路径，Memory 与 Observation 在送模前都应按事件 Sequence 合并，避免同一事件在两个字段重复暴露。

### P2：REVISE_POSITION 会无差别修改所有 ACTIVE 承诺

当前 `revisedCommitments()` 遍历已有 Commitment，只要 `status` 为 `ACTIVE` 就改成 `REVISED`，没有依据当前发言的目标玩家、被修正的观点、原承诺 Sequence 或语义主题进行筛选。

例如玩家先后公开承诺“反对 P2”和“支持 P4”，随后只针对 P2 进行立场修正，当前实现会把两条承诺都改为 `REVISED`。这会让后续 Cover Story 和矛盾检测丢失真实的未修正承诺状态。

证据：`avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:478-482,492-507`。

建议让 `REVISE_POSITION` 的动作结构显式携带被修正的 `supersedesSequence` 或目标/主题，由宿主只更新对应记录；如果动作没有提供可识别的旧承诺，则不要自动批量修改所有 ACTIVE 项，而应记录为新的立场声明并保留旧承诺。

### P2：Commitment 仍是字符串，且输出契约与持久化契约冲突

本轮通过正则提取 `sourceEventSequence`，缓解了字符串替换问题，但数据模型仍为 `List<String>`。这意味着状态字段、条件、目标和生命周期仍不受类型约束。

同时，主机在 `enrichPublicCommitment()` 中删除 `strategyState.publicCommitments`，而 Prompt 仍明确要求模型每回合填写该字段，且 `commitmentsToAdd` 仍存在于输出 Schema 但会被主机丢弃。模型看到的“已声明承诺”、模型输出的“计划承诺”和主机保存的“权威承诺”没有清晰的字段边界。

证据：

- `avalon-runtime/src/main/java/com/example/avalon/runtime/orchestrator/GameOrchestrator.java:470-472`
- `avalon-agent/src/main/java/com/example/avalon/agent/service/PromptBuilder.java:55,68-85`
- `avalon-core/src/main/java/com/example/avalon/core/player/memory/PlayerMemoryState.java:20,168-194`

建议引入强类型 `PublicCommitment`，将模型的 `proposedCommitments` 与主机的 `acceptedCommitments` 分开，并从 Prompt 中删除会被静默丢弃的正式写入字段。

## 3. 已确认有效的修复

- `publicClaimsToAdd` 不再被主机替换掉，Observation 中其他玩家的 Claim 可以进入 Memory。
- `appendBounded()` 按事件序列去重，永久重复 Claim 的直接存储问题已修复。
- 主机生成的即时 Claim 已补充 `actorPlayerId` 和 `eventType`。
- 私有知识校验继续使用最终解析出的 `PublicSpeechAction.speechText`，不再只检查原始 `publicSpeech`。
- 精确身份知识校验不再因候选知识列表为空而整体跳过。
- 普通问题、回答、挑战和观点不会自动写入正式 Commitment。
- 欺骗意图白名单、Merlin `exposureRisk`、非公开动作 Communication 校验和任务队伍事件归因未发现回归。

## 4. 战略能力判定

当前 Harness 已经建立了私有视图隔离、公共事件投影、跨回合 Memory、角色策略约束、Speech Act 和证据引用等必要基础设施，前身项目中“Agent 可以读取其他 Agent 私有信息”的致命问题没有重新出现。

但以下能力仍未得到行为验收：确定性 claim/vote/contradiction/team 工具、动态讨论调度、承诺兑现与撤回、角色人格差异、多 seed/座位轮换/真实 Provider 对局，以及能否通过欺骗获得真实胜率收益。

结论仍是：**架构已经允许 Agent 进行博弈，但还不能证明 Agent 会稳定地进行博弈。**
